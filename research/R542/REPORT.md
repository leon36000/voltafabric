# R542 — full layer-3 QSA weight decoder cross-check

For all 15,872 layer-3 Q, K, V and output projection rows used in R541, the actual local GGML C decoder output was streamed directly into a separate gguf-py/NumPy implementation and compared bit-for-bit with Python's decoded output. All 49,807,360 f32 values matched. Coverage is 12,288 IQ4_XS Q rows, 512 Q6_K K rows, 512 Q6_K V rows, and 2,560 Q8_0 output rows. A negative control altered one streamed decoded value; Python rejected it at Q row 0 and published no successful result. The source-shard descriptor identities, size and timestamps remained stable, and all five projection spans freshly matched the R430/R538 manifest hashes.

This cross-check reduces reliance on a single decoding implementation for the real R541 weights; both implementations still derive from the same GGML format and codebook lineage, so it is not independent validation of the format specification or authenticated publisher provenance. It does not independently validate the activation quantizer, layer inputs, remaining model, R428 expert-255 strict failure, GPU or distributed execution. No workers, generation, ledger claims or UNKNOWN operations were replayed. The Python reader streams the C decoder output without retaining a decoded copy on disk; only compact per-matrix digests are saved.
