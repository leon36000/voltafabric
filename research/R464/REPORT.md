# R464 — explicit transactional local CPU expert eviction

Parent R463 `c7d22283cdee20399af8aaeb5493f632f8057d60`. Extends the existing GGML/Strata-derived CPU path, not the donor engines as a whole. `Segment::evict_owner_after_commit` requires a globally committed position and a matching locally observed binding, checks source accounting and rank order, consumes an exclusive durable local eviction claim, and asks the worker once. Only an exact verified acknowledgement permits the source budget, registry and physical order to change. A reservation, transmission or acknowledgement failure poisons the segment; the claim remains consumed. The operation key includes the run/model/plan/layer/batch/epoch/expert identity and deliberately excludes attempt, physical placement and blob digest to block rerouting or rebinding as a replay. This local ledger is not the shared R53 hardware ledger or a distributed lease. The method is explicit: it does not choose a victim, automatically evict during pressure, persist successful reconciliation, or implement a general cache policy.

A fresh PC1 local CPU run of the SC117 48-layer path, with prompt `Hello!` (tokens `[9419, 0]`), explicitly evicted layer 0 expert 0 after the first globally committed position. The verified worker acknowledgement released 2,176,000 expert-payload bytes from the source budget. The next two positions completed, the same generated tokens `[1165, 3849]` decoded to ` We’ve`, and all 96 workers closed normally. Against R462 the three input token IDs and all three embedding and layer-output hashes and both logits hashes were identical. The payload accounting fell by precisely 2,176,000 bytes; this is not a measurement of RSS savings. The seeds and set of 907 admitted `(layer, expert, digest)` tuples match R462, whose independent local observer compared all 1,003 unique seed/admitted expert digests to the pack and GGUF slices. That comparison is local consistency, not authenticated checkpoint provenance or an independent full-model numerical oracle.

The run used a fresh local ledger with 144 batch claims and one eviction claim, all retained as `RESERVED_UNKNOWN_NO_REPLAY` in `CLAIMS.json`. It ran in a user systemd scope with MemoryHigh 11 GiB, MemoryMax 13 GiB, MemorySwapMax 0, TasksMax 320 and CPUQuota 300%. No GPU, inter-machine worker, R53 lease, or shared hardware operation was used. No rank-session process remained after the run. Local and PC1 Cargo.lock, manifest and changed execution-source SHA256 values matched.

Targeted debug tests passed: five ledger tests including changed attempt/binding and restart refusal, three worker/session tests including stale binding, replay and lost/wrong acknowledgement, and three source tests including atomic budget release. The success-path end-to-end run exercises the Segment integration; the Segment-level post-reservation lost-ack path is not independently exercised here, although the underlying session failure tests pass. Focused Clippy on the library, new binary, and selected tests passed. Broad Clippy over all historical tests/binaries was blocked by pre-existing `items_after_test_module` errors in `vf-sc117-eight-layer-origin.rs` and `vf-sc117-eight-layer-dynamic.rs`; those unrelated files were not changed.
