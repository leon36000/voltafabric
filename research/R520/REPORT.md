# R520 — cache locally verified source-expert digests

Parent GitLab R519 d9831bedd24ef87fb8df5c753093dfabe53d94f6. R519 had 8,196 dynamic expert admissions for 3,842 distinct experts, plus 7,085 evictions. The source validator previously reread and hashed three source-shard slices on each request, including re-admissions and eviction binding checks. `Origin` now stores a digest per validated (layer, expert) for the lifetime of that Origin. Every lookup first checks the pinned source descriptor identity and index digest; the first lookup still reads and hashes all three bounded slices and checks the descriptor again. Each pack payload and worker load remain independently digest-checked against that source digest. No expert payload is cached. The validated SC117 layout bounds keys to 48 x 512; cache storage and metadata overhead are outside the expert-payload budget and have not been measured as RSS.

This avoids redundant slice reads only while the source descriptor metadata is unchanged. Device/inode/size/mtime/ctime checks are change detection, not cryptographic publisher authentication or protection against a privileged adversary. A changed descriptor fails closed, including on a cache hit; existing operation/poisoning and UNKNOWN rules are unchanged. The idea is an independent VoltaFabric adaptation in the same general spirit as the Maya cache exploration R365, not copied Maya source and not an assertion about Maya's implementation. No throughput gain is claimed.

The v10/r520 plan binds `stable-source-digest-cache-v1`. The result receipt exposes successful hit/miss/entry counts, not timing or a proof of I/O behavior. The independent plan encoder matches Rust's vector. Three Origin unit tests passed in debug and release. A new test uses a sparse unlinked test descriptor, verifies the known zero-payload digest independently, verifies a cache hit leaves file position unchanged, then modifies the descriptor and confirms refusal without increasing the hit count. Four prefill binary tests passed in debug and release, targeted Clippy passed, and 33 PC1 tokenizer/adapter/chat tests passed with the real tokenizer.

On PC1 a separately scoped read-only CPU probe opened the locally observed SC117 shard and checked layer 2 expert 255 twice against the prior independent R473 digest. It reported one miss, one hit and one entry; both probe invocations exited zero, with the second result preserved as ORIGIN.json. The source is locally consistent, not publisher-authenticated. The probe used 128 MiB, zero swap, eight tasks, one CPU and low I/O priority. No worker, model generation, GPU, SSH worker, shared lease or consumed claim replay occurred. The changed cache has not yet been qualified in a full real-model generation.
