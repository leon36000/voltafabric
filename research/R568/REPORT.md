# R568 — four real CPU layers, including QSA, in layer-major batches

Qualifies R567's existing multi-layer batch path with actual SC117 layers 0–3: three GDN layers, layer-1 PLE and layer-3 QSA. One bounded PC1 CPU run fed the real checkpoint embeddings for supplied token IDs 42 and 73 through the four layers. Two seeds per layer were resident; 66 route-selected experts were admitted dynamically after their pack bytes matched observed GGUF source slices. Eight guarded local rank workers each processed one grouped request and exited normally. The two final residual hashes match R454's historical sequential results exactly. R454's complete four-layer preview shares numerical implementations, so this is not independent full-layer or full-model parity; R453 separately checked PLE against NumPy, and R436 checked a different QSA input.

A separate fresh fault run was budgeted to complete layers 0–2 and admit one layer-3 expert before refusing. The segment produced no output, remained terminal at its initial public position and refused further work. PLE state had already advanced through its successful earlier layer, which is expected: a later failure poisons the entire segment rather than rolling previously committed internal states back. All eight fresh claim receipts remain RESERVED_UNKNOWN_NO_REPLAY and are included. Both cases used four layers, not the full model.

The run used a PC1 CPU-only scope capped at 6 GiB RAM, zero swap, 100% CPU quota and 128 tasks; no GPU or inter-PC worker. The R568 diagnostic and library passed Clippy with the pre-existing trace-only dead_code allowance, and rustfmt passed. Production code is unchanged from R567, whose debug and release library suites each passed 134 tests with five ignored. No throughput, full generation or distributed qualification is claimed. The 66 source slice matches are local observations, not authenticated model provenance.
