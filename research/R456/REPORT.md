# R456 — checkpoint-derived route-driven expert admission

Parent R455 `90bb169ea3fe93105500cf21e0fad3d5216f628e`. `sc117_expert_origin` derives each expert digest on demand from three bounded gate/up/down slices in the pinned SC117 GGUF source, using the pinned observed native index and quantization-specific geometry. It verifies the source descriptor identity and metadata before and after each read, checks expert, geometry, offset, file and allocation bounds, and leaves pack-byte verification to the existing digest-checked native reader. The source and index identify the locally observed files, not an authenticated publisher or checkpoint; external provenance and tensor metadata remain caller responsibilities. This adds no assumption that IQ3, QPN2/NVFP4 and MXFP4 are interchangeable.

A fresh identified PC1 CPU run processed supplied token IDs 42 and 73 through eight real layers, PLE and 16 local worker sessions. Each layer began with fixed experts 0 and 1, chosen without a preview route. The actual gates requested 134 other experts, and their source-derived hashes were computed at admission without a preview-derived digest allowlist. All 16 workers completed both positions and returned clean BYE. Total resident expert payload was 295,833,600 bytes under a 512 MiB diagnostic cap; this excludes stage weights, buffers, process overhead and peak RSS. No eviction or general production cache is implemented.
