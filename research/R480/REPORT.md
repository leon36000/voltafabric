# R480 — rejected shutdown after first accounting change

The R479 diagnostic identified a worker-shutdown refusal, but not its specific predicate. R480 changed the prefill qualification to compare each worker's BYE count with its session traffic counter and retained the other shutdown checks. The bounded fresh CPU run on PC1 again ended with `worker_shutdown, exit=1` and no result; no workers remained. Inspection then showed that the native GGML EXEC path did not increment `Session.traffic.execs`, so using that counter without changing the native path was incorrect. This is a definite defect in the attempted correction, not proof that it was the only reason for the refusal. R481 adds the missing counter update and requires fresh validation.
