# R522 — bind the exact prompt in strict generation receipts

The prompt runner previously checked that `input_tokens` started with the actual tokenized prompt, but `decode_greedy_receipt` used the receipt's separately supplied `prompt_tokens` to interpret the autoregressive sequence. A receipt could claim a shorter prompt and present a prompt token as generated text, while retaining the correct full-prompt digest. A focused two-token regression reproduced that acceptance against the R521 parent before the change.

Strict bound-plan mode now requires `prompt_tokens` to equal the actual token IDs, with each element an integer and not a boolean. Missing, shortened, extended, null and boolean-containing prompt fields are refused before text is returned. Explicit legacy `require_bound_plan=False` keeps its previous behavior. This is original VoltaFabric validation around the previously traced Strata tokenizer; it does not authenticate a plan, engine, checkpoint or remote host, or replace admission and ledger rules.

On PC1, 34 tokenizer, adapter and chat tests passed with the observed tokenizer pack and its existing Strata virtual environment, with no skips. The regression failed as intended before the fix and passed afterwards. `verify_real_receipt.py` checks the SHA256-pinned R521 real result, accepts its `Hello` text and refuses modified/missing prompt fields without starting an engine. Testing used a fresh small CPU scope (512 MiB, no swap, 16 tasks, one CPU, nice 10); no worker, GPU, network worker or consumed claim ran.
