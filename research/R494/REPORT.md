# R494 — bounded SC117 text-only chat prefill

Parent GitLab R493 be9235b10a64454a360aa2ded788be473478eed1. The existing MIT-licensed Strata tokenizer (provenance R460) can identify SC117's control tokens. The observed template is a checkpoint reference, not a publisher-authenticated guarantee.

`prompt_runner --chat` now supports exactly one text-only user message, no system, tools, vision or prior turns, matching the observed template with enable_thinking=false and generation prompt enabled. It inserts trusted role/think markers but encodes all user message text as a plain span so literal special-token strings cannot add control tokens; this intentionally differs from naïvely parsing every literal in untrusted user text. The exact expected control sequence and tokenizer types are checked, as is the 32-token/39-position existing bound. No arbitrary Jinja executes in the production path.

The prefill binary accepts an explicit `chat` mode after EOS. In plain mode it continues to reject EOS in the prompt; in chat mode it can prefill the in-band end-of-message/EOS token without treating it as generated termination. It records prompt mode in the result and version-5 plan, and the Python runner rejects a receipt whose mode differs. The updated Python runner and engine are a coordinated pair. Both modes remain bounded and require a fresh ledger and all external admissions.
