# R562 — provisional SC117 GDN attention stage

Adds a bounded multi-position GDN stage which loads and projects real SC117 weights, advances a private copy of convolution/recurrence state, and publishes it only after all positions succeed and its caller commits. A failed, incomplete or wrong-identity batch leaves the resident state and token cursor unchanged. The existing single-position path uses the same projection function. This stage-level CPU API is unreserved: the enclosing caller must bind a fresh ledger claim, validate every routed/shared output and atomically finish the whole layer before commit. R561's standalone GdnBatch is not called here; this stage keeps its own candidate to permit mutable quantized projection.

A bounded PC1 CPU check loaded observed layer-4 SC117 IQ3 QKV and associated dense tensors (manifest SHA e828fe4e01fe8c9a86201b79fa40f6e29ceca325b2d0a4ca9be954a939d8afca), using the existing input SHA 653f8385328f68ebebfe966082717b7c566053d540081b0539d5e0370ea15b65 and a second input scaled by 1.001. The first output exactly matched R432's historical output, for which independent NumPy checks were previously documented. The two batched outputs matched serial stage execution bit for bit, including the second recurrent step. Failed, incomplete and foreign-identity batches were rejected; the next output matched the serial continuation after rollback. This is not an independent two-position model oracle, and the second input is synthetic, not a generated token.

The diagnostic used a fresh isolated work directory and a CPU-only systemd scope (1 GiB memory, zero swap, one CPU quota), without ledger claims, workers or GPUs. `cargo test --offline --locked --features native-ggml-cpu --test sc117_gdn_stage` passed in debug and release; the native-feature library and diagnostic passed Clippy `-A dead_code -D warnings` (the allowance is for the pre-existing trace-only struct). Rustfmt passed.
