# R563 — reservation-bound GDN layer batch with real CPU experts

Adds a local CPU GDN `RoutedBatch`: one fresh native reservation binds GDN provisional state, post-attention routing, shared expert, actual expert sessions and the Rust native Collector. Producer markers and stamp/attempt/ledger identity must match; all output rows and residuals are validated before GDN state commits. The code follows the existing R557 QSA transaction and retains Collector decoded FP16/f64 behavior, not a PyTorch index_add approximation. The local ledger is not the shared hardware R53 ledger or a distributed lease.

On PC1, one bounded CPU run with observed SC117 layer-4 weights used two residual positions (the second is the first scaled by 1.001). Their union contained 11 real selected experts across two guarded local rank workers; each expert blob hash matched the corresponding GGUF source slices, as recorded in OBSERVATION.json. Both batch residuals exactly matched two serial native-Collector executions; the first also matched R432's independently reconstructed residual SHA 73f76dfe1165e8297193da3222b835d820aacb69e7a094d7d69de60fed9fe08d. The second is a same-implementation sequential comparison, not an independent multi-position oracle. Rejecting an invalid second input and mixing a foreign shared marker after actual collection left GDN state and token cursors unadvanced. Both workers exited normally after four executions each. The plan and result, observation and all six fresh claim receipts are included; every claim remains RESERVED_UNKNOWN_NO_REPLAY.

The actual CPU run used 3 GiB maximum memory, zero swap, 100% CPU quota and at most 64 tasks. No GPU or network worker was used. Native-feature Clippy passed with the pre-existing trace-only dead_code allowance. The SC117 GDN stage integration test passed in debug and release; rustfmt passed. A broader debug library test did NOT pass in the isolated PC1 worktree: 123 passed, 10 failed, 5 ignored. Failures include pinned-directory, artifact/origin, layer-chain and MXFP4 session tests, some reporting SESSION_CLOSED. Their causes have not been established; no full-suite pass or release library run is claimed.

Scope remains one local layer and two positions, not a complete prompt or model; no hardware/distributed or performance claim. Next: independently check nonzero recurrent positions, resolve the broader library test failures in a representative environment, and connect reserved GDN/QSA and PLE batches to a layer-major full prefill while preserving fresh attempt admission and UNKNOWN no-replay.
