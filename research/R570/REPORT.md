# R570 — 48-layer CPU generation after grouped prompt prefill

Adds opt-in `VF_PREFILL_GROUP_SIZE=2` to the existing SC117 CPU generation coordinator. Prompt positions are processed in causal groups of two using the R569 reserved layer-major batch path; an odd final prompt position and generated tokens retain the existing single-position path. A distinct `r570-` plan hashes the unchanged base plan with an explicit batch-policy domain. The tokenizer runner accepts the new bound plan prefix. Grouped mode currently refuses SSH workers and QSA tracing, retains the guarded layer-1 PLE qualification constructor, and reserves worst-case payload for two tokens before batch execution. This bound covers expert payloads only, not peak RSS or arbitrary future eviction feasibility. Default single-position mode keeps its prior plan. No external engine code is copied in this slice.

Two distinct fresh PC1 CPU runs with 48 SC117 layers and local actual expert workers used the first two supplied chat-control prompt tokens of R552 (248045, 846). The first generated token 198 after the grouped prefill. The second generated IDs 198 and 1; it fed 198 back through all layers before producing 1. All three corresponding full-layer residual hashes exactly match the first three positions of the historical R552 sequential trace. This is same-implementation regression evidence, not an independent whole-model oracle or a meaningful conversation-quality test; the short input is an incomplete chat prefix. The first run dynamically admitted 835 experts and the continuation run 1093; each closed all 96 guarded local workers cleanly. No hardware worker or GPU was used, no eviction occurred, and input tokens were supplied rather than produced by a tokenizer in these two runs.

Each run had a distinct externally recorded plan, exclusive submission marker and fresh local ledger. `CLAIMS.json` and `CLAIMS_CONTINUE.json` aggregate the exact record, original filename and original SHA-256 of all 48 and 96 claims respectively; each remains RESERVED_UNKNOWN_NO_REPLAY. Neither ledger is the missing shared R53 or a hardware lease. Runs used MemoryHigh 11 GiB, MemoryMax 13 GiB, zero swap, 200% CPU quota, 320 tasks and low scheduling/IO priority. No throughput comparison is claimed.

The new plan identity test first failed because the helper did not exist, then passed. Nine coordinator unit tests passed debug and release, Clippy passed with the existing trace-only dead_code allowance, rustfmt passed, and 34 tokenizer runner tests passed using PC1's existing regex environment. PC6's default Python lacked regex; that failed import was not treated as a pass. A Python SHA-256 reconstruction independently confirmed the two-position plan-domain transform. Full model parity with an independent engine, longer prompts, odd-length prompts and tokenizer-to-engine end-to-end grouped mode remain unqualified; arbitrary future routes may exceed the bounded headroom. Distributed V100/other machine execution and GPU/RDMA remain separately gated.
