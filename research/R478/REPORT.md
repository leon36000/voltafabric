# R478 — experimental rank-aware pre-position headroom

Parent GitLab R477 commit b18637a277f6ac33b684b09f3c1ad5a298607b71. This branch is experimental. The existing CPU segment now computes an eviction plan against both the global target and a target for the highest-capacity rank (ties choose the lower rank). When per-rank caps are enabled it aims to reserve the complete worst-case next-position expert payload on that rank, then satisfy the global target. This conservative strategy can reject workloads that could fit with a more sophisticated distributed reservation. When no single rank can hold the requested reserve it refuses before dispatch. With no per-rank caps the previous global policy is retained.

Planning is complete before evictions are sent, applies checked arithmetic and a 768-eviction bound, keeps one resident per (layer, rank), and excludes the last committed route. Each actual release still requires a worker acknowledgement and updates both counts. If an eviction fails after earlier acknowledgements, the segment remains poisoned; no partial position is published. No physical memory, lease, network topology or real inter-machine placement is certified.

The 10 sc117_layer_chain unit tests passed both debug and release, and library Clippy passed with warnings denied. The rank test covers choosing a constrained rank before an older global candidate, both targets, a too-small eviction bound, invalid accounting and protected last residents. A fresh local CPU PC1 run with a fresh R478 identity and ledger used 48 layers, two local rank labels, 1 GiB and 2 GiB rank caps, 3 GiB global cap, 8 predictions, and bounded CPU/memory scope. The engine still failed: runner classified the failure as unclassified and published an empty output. There were no rank workers after refusal. We cannot infer committed positions, successful evictions, the cause, or a complete generation from the claims.
