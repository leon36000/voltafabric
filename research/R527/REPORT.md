# R527 — sealed, plan-bound SSH host-key input

The SC117 SSH endpoint previously relied on the machine's ambient known-hosts configuration. For each SSH rank, v13/r527 now requires `VF_RANK{rank}_SSH_KNOWN_HOSTS` and `VF_RANK{rank}_SSH_KNOWN_HOSTS_SHA256`. The bounded file must contain exactly one Ed25519 entry for the configured alias and match the externally supplied SHA256. Its canonical path, digest, host alias and SSH options are bound into the plan. A missing or mismatched pin refuses before weights or workers.

On Linux, the checked bytes are copied into a sealed memfd held alive by the coordinator until all sessions close. The plan uses the canonical input path, while runtime SSH reads `/proc/<coordinator-pid>/fd/<fd>`. Original-file changes cannot alter the sealed snapshot. SSH uses that file exclusively, disables global known-hosts, DNS host-key verification, key updates, known-hosts commands, proxy commands/jumps, local commands and forwarding, and sets the approved host-key alias. This is an original VoltaFabric integration, using rustix 1.1.5 safe fs APIs; its declared license is Apache-2.0 WITH LLVM-exception OR Apache-2.0 OR MIT. The existing Cargo.lock had this version as a transitive dependency; it is now direct on Linux.

On PC1 five focused Rust tests passed in debug and release, and 34 Python tokenizer/adapter/chat tests passed with the observed tokenizer. The sealed-file test rejects wrong host and digest, verifies writes to the snapshot fail, changes the original without changing the snapshot, verifies a child can read the coordinator descriptor, and checks `ssh-keygen -F` plus `ssh -G` effective host-key settings without connecting. A no-worker real plan-only preflight used two synthetic Ed25519 public values for the same alias and path: the independent oracle reproduced two different v13 identities; an incorrect expected digest was refused, with no worker or ledger claim. The synthetic public values are not actual host identities or credentials. The first compile failed because the repository forbids unsafe Rust and the provisional test referenced an unavailable dependency; the implementation was revised to rustix safe APIs and the successful tests are those described above.

The coordinator SHA256 was `53b082e01a9b71a2addf38bde7c8407a0d0884b922cfb916633dab650da92947`; worker SHA256 `49216f6ce76a637be323dd0aa88c69e7788b4fa8ff13f5663ee103c5e4a22409`. Builds used at most 3 GiB/no swap/64 tasks/150% CPU and preflight 512 MiB/no swap/16 tasks/one CPU. No SSH connection, remote worker, model generation, GPU, R53 reservation or UNKNOWN replay was performed.

This only constrains SSH to the bytes whose digest the caller supplied: the owner must independently authenticate that digest and host identity. It does not establish a real shared lease, verify remote runtime/model identity, qualify distributed generation or override resource and hardware gates. PC6 swap remained below the 1 GiB inter-PC floor. The known-hosts format is intentionally limited to a single literal alias and Ed25519 key. Next qualify local v13 generation and separately integrate the real shared lease and authenticated host/worker identities before any inter-PC attempt.
