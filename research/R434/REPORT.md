# R434 — persistent reservation-bound CPU layer segment

Parent R433 `4bdfb95be70d5d265c5071c2189285c1d29f7632`. The new `sc117_layer_chain::Segment` owns resident GDN or QSA stages, their shared stages and per-layer sessions. It admits contiguous layers with a common run/model/epoch and an explicit plan, issues a separate durable reservation for each layer, passes residuals in memory, and publishes only the final segment result. A failed step poisons the segment: earlier state may already have advanced, so it cannot be retried or reused. Input and attempt rejection before the first reservation does not poison it. `close` returns the actual worker shutdown receipts. The local native ledger is not the shared R53 lease and does not authorize GPU or inter-machine work.

One fresh local CPU check on PC1 executed layers 4 and 5 in **one Segment and one run identity**, with a synthetic input, two local owner processes per layer and ten actual routed resident experts per layer. This is the first tested in-memory chain of two actual complete layers in this work; it is not generation or a full model. Each layer used the ordinary FP16-decoded, f64 Collector, applied its route once and combined its shared expert. The result compared equal as f32 values to a separate in-process preview which used the same native provider and Rust completion implementation: this is a useful integration cross-check, not an independent numerical oracle. Four workers returned normal shutdown receipts with one execution each. `RESULT.json` records the actual run, attempt, selected experts and hashes. Its SHA256 is `90a9ba38e1bcd95bdc08b2d6981678f8dcdf7078b1659bfe72df0ccf94e331cf`.

`WEIGHTS.json` records SHA256 of all twenty local expert blobs and their exact comparison against the corresponding three slices in the observed GGUF. Local matching and observed manifests do not authenticate model provenance. The generated layer-5 manifests bind local dense and GGUF spans; layer 4 reuses R432 manifests. The two copied claims remain `RESERVED_UNKNOWN_NO_REPLAY`; do not replay them even though this particular observation completed. The CPU prefix previews have no remote owner submission or durable reservation. No GPU or inter-PC worker was run.

Three scheduler tests passed debug and release: ordered in-memory handoff across two tokens, durable claim consumption and terminal behavior after a later-layer error, and rejection of invalid input or a repeated attempt before reservation. These use controlled step collaborators and a real local ledger; they are not multi-token model tests. Native-feature library and diagnostic Clippy passed with warnings denied, and changed Rust files passed formatting. The real two-layer check exercises GDN only; its QSA branch, failure after a real remote dispatch, multiple tokens and layer-chain numerical parity against an independent model remain unqualified.

This adapts existing VoltaFabric transaction and CPU owner code, including the GGML/llama.cpp and Strata native boundary documented in `adapters/native_ggml/README.md` (pinned MIT sources). It does not establish inherited donor quality. R428's expert-255 scalar threshold discrepancy is unresolved. The 48-layer model, general QSA formats, full tokenizer/head path, real distribution and hardware admission remain outstanding. Next: verify the QSA-to-GDN segment with fresh inputs and real owners, then generalize the loader and resident placement before attempting full generation.
