The Strata tokenizer adapter now offers `--prepare-plan` (and `prepare_plan=True` in the library) using the same prompt validation, chat template, tokenization, EOS and generation limits as the normal path. It invokes the R516 CPU engine with `--plan-only`, requires an exact two-field plan receipt with a current-shaped plan ID and matching little-endian token digest, checks any caller-supplied `VF_EXPECTED_PLAN_ID`, and returns the plan plus token IDs without decoding generated text. Invalid, duplicate, oversized or inconsistent plan receipts fail closed. The existing bounded subprocess capture remains capped at 32 MiB stdout and 64 KiB stderr; the 1 KiB plan receipt limit is checked before JSON parsing, not a 1 KiB subprocess memory cap.

This is original VoltaFabric glue around the already traced Strata tokenizer, not copied source. Preparing a plan does not authenticate the host, executable, checkpoint, or prove a shared lease; the CLI hashes its supplied binary before launching it, but the supplied expected binary hash is still a caller responsibility. It is not a plan reservation, does not validate complete model weights, and must be followed by real external admission, R53 reservation and all applicable gates.
