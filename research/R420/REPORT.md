# R420 — collector-gated CPU GDN candidate commit

`sc117_layer_completion::finish` connects the existing ordinary Rust FP16/f64 Collector to the SC117 shared and residual arithmetic. It accepts exactly one 2560-wide routed token, full routing metadata, unweighted rank packets, a separately pre-scaled shared row, the post-attention residual and FFN injection. It validates stamp/attempt equality and shapes, asks the existing Collector to admit every slot and reject duplicates, stale attempts, missing rows and invalid binary16, accumulates in canonical slot order with route weights once, adds shared once in f64 and casts to f32, then applies hyperconnection write. The complete residual is returned only after all checks succeed.

`Stage::commit_collected` now performs that completion before committing the R419 candidate and process-local token index. It checks stage instance, exact candidate stamp, attempt and token against the completion. The previous public `commit_validated` escape hatch is private. If any validation or calculation fails, the candidate is dropped and the resident GDN state remains unchanged. This is an in-memory boundary, not durable or end-to-end production transaction: callers remain responsible for authenticating worker/shared/residual provenance, connecting the actual post-attention/FFN computation to this candidate, and enforcing an externally durable reservation and no-replay after UNKNOWN. Stamped caller-provided data alone does not prove execution or mathematical correctness.

A small independent synthetic fixture sends two ranks in reverse arrival order with weights 0.25/0.75, FP16 values 1/2, shared 0.5 and residual 3: every resulting value is exactly 5.25. Tests refuse missing or duplicate rank rows, wrong attempt, stale shared stamp, wrong injection length, nonfinite shared values and nonfinite FP16. The existing Collector tests retain full stamp/slot coverage. On PC1 the real layer-2 GDN prefix used a synthetic zero expert/shared completion to exercise this wiring: wrong attempt, changed batch, missing routed row, stale candidate, duplicate token and NaN activation were rejected without advancing; one synthetic completed transaction advanced. The prefix was byte-identical to R418 SHA `ab5f3832fda74a81d41ae2c574d9ac21c977029b387de5d2c4ca90f76a47fe77`. This does not execute actual layer-2 experts or prove a full layer.
