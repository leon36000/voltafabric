# R181 — session Rust persistante entre appels MoE CPU

`examples/r181_persistent_cpu_session.rs` conserve en mémoire une vraie Session Rust par propriétaire et les artefacts QPN2 pendant plusieurs requêtes FP16. Le prototype prend une configuration initiale et des lignes JSON bornées ; chaque batch doit avoir l'identité suivante et ses propres routes et coefficients. La session appelle `run_compressed_batch_with_fp16_inputs`, sans récupération ni rejeu, et ne renvoie la sortie que si le batch est complet. Elle ferme les workers à la demande. `donor_hook.py` fournit l'interface à six arguments appelée par la méthode MoE du donneur extraite par AST.

Tests CPU après compilation `cargo build --offline --locked --example r181_persistent_cpu_session` : trois tests, exit 0. Le test appelle deux fois la vraie méthode extraite avec les mêmes activations et les coefficients 0,25/0,5 puis 0,125/0,25 : ses sorties FP16 correspondent respectivement à 0,75 et 0,375 fois la référence capturée de 2 048 valeurs. Les deux workers réels chargent chacun une fois leurs poids et exécutent chacun deux batches ; BYE rapporte deux exécutions. Le test direct du coordinateur vérifie les mêmes deux résultats en f64 et la fermeture ; un batch d'identité répétée est refusé sans résultat partiel. Le run direct positif est `r181-4da788dd6e35450eaa6c770057f616ca`, sortie SHA256 `47f0793a8810d2ff6e19e47c2d9d0590b593510304ba2e73bc28d02def028b40`. Le run négatif distinct `r181-c4153c2f0908479485263dd01b5518d1` est consommé, sans rejeu ; sa sortie SHA256 est `c9824545496b1d5114716a7edade749763c2d9ce7347db669204873c91651341`. Aucun processus de test restant constaté après les tests.

Vérifications supplémentaires : `rustfmt` sur le fichier, Clippy ciblé `--offline --locked --example r181_persistent_cpu_session -- -D warnings` exit 0. Le binaire SHA256 `f6651fc02e4295c3877268d3e99226a6d27b620d69e51ad906874aa8bf68bf5e` est un build CPU local.

Limites : cette couture reste privée, mono-processus coordinateur avec workers locaux CPU et un seul token, deux routes, un expert synthétiquement dupliqué et fournisseur CPU de test. L'extraction de méthode ne charge pas 1Cat entier. La couche Python n'a pas encore de délai borné de lecture ni journal durable d'identités à travers un crash ; elle n'est donc pas qualifiée pour les pannes de production. Les experts partagés sont refusés. Il reste à développer le raccord runtime réel, la gestion durable des issues inconnues, les formes générales, les ressources et transports, puis à qualifier un modèle entier et le GPU. Aucun débit ou résultat de génération n'est affirmé.
