# R487 — bounded concurrent capture of engine receipts

Parent GitLab R486 commit 5fcd5dea9d31b9dfe068487eecc69dd8a81bc2c7. The Python prompt runner previously used subprocess.run, buffering stdout and stderr completely before checking a size limit. It now drains both pipes with a selector and retains at most 32 MiB of stdout and 64 KiB of stderr. Further bytes are discarded while the engine continues to be drained, allowing normal worker shutdown; the runner does not kill or retry the engine. A truncated success is refused before JSON parsing. A truncated failure is unclassified and its contents are never published. This bounds captured byte prefixes, not total process RSS: converting to bytes and parsing JSON can allocate additional memory. No internal time limit is introduced; a stuck process or a descendant that keeps a pipe open still requires the caller's external resource/lifetime controls.

On PC1, the tokenizer test suite ran 19 tests: 18 passed and one observed-pack test was skipped. New tests use real subprocesses to write beyond both pipe capacities without deadlock, test exact bounds, refuse truncated successful output and avoid classifying a truncated error, and decode a complete 2 MB synthetic receipt over a real pipe. These tests do not establish network behavior.
