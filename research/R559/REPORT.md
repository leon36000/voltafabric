# R559 — pre-batch QSA expert headroom and eviction identity

The QSA segment can now trim accounted expert payload between completed batches before admitting the next batch. It rejects insufficient QSA cache capacity before issuing any eviction. The existing planner protects the union of experts selected by the previous batch and retains at least one resident per rank. It uses caller-provided bounded headroom, does not predict the next route or measure process RSS, and uses the existing conservative single-rank rule if rank caps are configured. Failure after a submitted eviction or batch reservation leaves the segment terminal; UNKNOWN operations are never replayed.

R558 exposed an identity mismatch: a two-position batch starting at position 2 leaves the cursor at 4, while workers remember batch 2, not position 3. The segment now records the actual start of the last committed batch. It also records which ranks participated and only plans evictions on those ranks; a direct eviction from an idle rank is rejected before reservation. Single-position execution records the same information.

On PC1 CPU, three two-position layer-3 batches from the recorded real prompt were compared with six sequential runs using real GGML expert owners. All six residual hashes matched. A 78,848,000-byte expert payload limit and 39,424,000-byte requested headroom led to eight acknowledged evictions before the third batch, each bound to the preceding batch start 2 and its attempt. Both batch workers closed normally. A subsequent over-capacity request was refused without changing the live state, source accounting, or ledger claim count. The test was performed twice under distinct plans and identities; each run's six sequential claims, three batch claims and eight eviction claims remain RESERVED_UNKNOWN_NO_REPLAY. The returned outputs and acknowledgements are evidence of what completed, not permission to replay.

The targeted eviction-planner unit test and native-feature Clippy passed on PC1; Clippy allowed the existing trace-only dead-code warning. Rustfmt passed. This compares paths sharing native kernels, not an independent full-model oracle. Rank-specific headroom alternatives, idle-rank rejection and eviction failures were not exercised in this live batch test. The operation does not qualify GDN/PLE, multi-layer prefill, GPU, inter-PC transport or speed.
