# R606 — couche réelle et experts scalaires dans une transaction locale

Sur PC1, une nouvelle transaction CPU a exécuté successivement l'attention GDN, le post-attention et son gate, l'expert partagé, les dix experts routés dans deux workers locaux et le Collector, puis a validé le nouvel état GDN. Les dix experts proviennent du checkpoint SC117 observé ; l'entrée est un résiduel d'essai dérivé du modèle, pas un token généré. Le routage, ses coefficients et l'activation reproduisent R428. Les workers ont chacun exécuté un batch et se sont fermés normalement ; le compteur GDN est passé de zéro à un.

Le Collector scalaire a le SHA-256 `ef0a699feb2e5d21cea882c1f7c8cbd517883a2de419e0c511aa91e784514ac5`, identique à la collecte R604 préparée séparément sur PC6. Le résiduel effectivement validé a le SHA-256 `0350630913cfe2b369d8bc7043e2cbeae352910229468516a6d55aa960173e90`, identique à la reconstruction hors ligne R605. Le vérificateur Python recalcule 10 240 valeurs depuis les sorties intermédiaires réellement produites sur PC1 et le Collector R604 ; il vérifie aussi le reçu, les coefficients, le GDN historique et l'identité du claim. Les valeurs des entrées et sorties issues du modèle restent sur les machines ; seuls les hashes et métadonnées sont publiés.

La référence de réduction R604 et les experts de cette transaction partagent les décodeurs et quantificateurs GGML épinglés de llama.cpp (`3cf03257f219afbe7334045ff7c6a06ac68c627d`) : ceci ne qualifie pas un oracle complet indépendant des experts. La reconstruction Python utilise `expf` du système, comme le calcul Rust. Les tranches d'experts sont vérifiées contre les observations R428, ce qui n'authentifie pas le checkpoint. Les formats IQ2_S et IQ4_NL observés restent distincts de MXFP4 et NVFP4.

Le plan externe, le code et les binaires sont identifiés dans `PLAN.json` et `RESULT.json`. Un marqueur exclusif a précédé l'unique essai ; `CLAIM.json` reste `RESERVED_UNKNOWN_NO_REPLAY`. La portée était limitée à 4 Gio, zéro swap, deux cœurs et 64 tâches ; les métadonnées des fichiers du checkpoint étaient inchangées après l'essai. Aucun GPU, worker inter-PC ou registre R53 n'a été utilisé. La compilation isolée, rustfmt et Clippy ciblés passent ; la cible de test du petit exécutable ne contient pas de tests unitaires. L'oracle effectue les contrôles numériques réels décrits ci-dessus.
