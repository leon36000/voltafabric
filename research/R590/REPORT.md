# R590 — full scalar witness on two CPU builds

A bounded CPU-only diagnostic compares the entire scalar path for three real observed SC117 layer-2 experts (12, 75, 255) with the same R428 activation on PC1 x86_64 and PC6 AArch64. The layer's gate/up weights are GGML `IQ2_S` (type 22); down weights are `IQ4_NL` (type 20). The checkpoint's overall IQ3 label does not mean every tensor is IQ3, and none is MXFP4 or NVFP4. The diagnostic uses the pinned GGML format traits and Q8 quantizers, explicit scalar double dot accumulation, f32 intermediate values and `std::exp`. Both C++ diagnostic sources use `-O2 -ffp-contract=off`; host compilers and GGML library binaries differ. GGML headers match the pinned `3cf03257f219afbe7334045ff7c6a06ac68c627d` checkout.

For each expert, all 31,760 captured bytes are identical across hosts: Q8_K input, 640 gate values, 640 up values, 640 activated values, Q8_0 intermediate and 2,560 f64 down outputs. For expert 255, the common scalar output differs from the retained PC1 vector provider beyond the original strict tolerance at 1,169 elements (max 5.4019493063606205e-5); PC6's retained vector provider has zero violations (max 3.0669013995066052e-9). This independently reproduces the R428 failure against a scalar result now observed on both hosts. It does not qualify cross-host scalar determinism for other inputs, layers, formats, math libraries, GPU kernels or a whole model; GGML decoders and quantizers are shared, and checkpoint provenance is not authenticated. A production scalar mode or a performance gain is not claimed.

The exact source actually compiled is `scalar_capture_executed.cpp`. Its first comment incorrectly labels type 22 IQ3_S; it is retained unchanged for hash fidelity. `scalar_capture.cpp` corrects only that comment, and `verify.py` checks the sole difference. Input expert slices were previously locally compared with GGUF source spans; their hashes and binary/library hashes are in the plans. The output captures and model-derived bytes stay local; `verify.py` independently parses them, checks all bytes/finite values, compares retained vector outputs and writes `RESULT.json`. The initial expert-255 plan and the subsequent two-expert plan preceded their respective executions. Each host used a CPU scope capped at 512 MiB, zero swap, 50% CPU and 16 tasks. No GPU, network worker, R53 lease or UNKNOWN replay was used. The real shared ledger, cooperative lease, model-level oracle and distributed generation remain open.
