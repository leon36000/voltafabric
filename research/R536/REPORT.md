# R536 — failure-atomic QSA qualification trace boundary

The SC117 CPU Segment now offers an opt-in `advance_token_with_headroom_qsa_trace` API under `ple-cpu-qualification`. It selects an existing QSA layer before any eviction, captures that layer's committed QSA output in private memory and releases it only after all layers for the position have committed. The returned trace carries the full Segment stamp (run, model, plan, layer, batch and epoch) and attempt. A missing/non-QSA layer is refused before eviction or reservation; a missing committed trace after segment completion poisons the Segment and returns an error. The ordinary headroom API continues to use the same scheduling path with capture disabled.

A targeted unit test uses a drop witness to verify that an observation created at an early layer is destroyed and never returned when a later layer fails, while a successful full position returns the observation. This exercises the actual observation-release helper but does not simulate real worker failure or prove end-to-end trace data. Thirteen targeted chain unit tests passed in debug and release; two worker-dependent tests were ignored and not claimed. Targeted release Clippy with `-D warnings`, rustfmt check, and a separate library check with only `native-ggml-cpu` passed on PC1. The first test compile encountered missing test fixtures, and the first execution lacked the test `.runs` directory; after restoring the specific bounded fixtures and creating that directory the tests passed. Test claims are fresh local synthetic identities and must not be replayed.

No generation, real trace capture, hardware lease, GPU or inter-PC operation was performed. The existing generator does not yet call this API. Next bind an explicit trace mode to a new immutable plan identity, cap and publish trace output only after complete successful generation, and use a fresh local run to feed R535's independent QSA oracle. Continue the R428 precision investigation and require an actual reconciled R53 ledger and all fresh admissions before distributed/hardware work.
