# R506 — bind actual prompt tokens to the worker plan

Parent GitLab R505 bf42a0cddf6b787c209ff1f376d41822bb9ba4eb. In the previous v5 descriptor two different prompts of equal length produced the same plan ID when other settings matched. Run IDs still differed, but the plan alone could not identify its prompt. The SC117 generator now hashes its validated prompt IDs as consecutive little-endian u32 values and includes that SHA256 and length in the version-6 plan. It records the same digest in the success receipt. Different same-length prompts and different orders produce different plan IDs; plain/chat EOS rules and existing 32-token and 39-position bounds apply inside the plan builder as well as the CLI.

The Python prompt runner independently checks a receipt's digest against its own token IDs whenever the field is present, and requires it for an r506 plan. Earlier receipts without this field remain accepted by the previous compatibility path. A digest and plan are not authenticated attestations: the caller still verifies the executable, model, remote host, resource admission and shared lease. Checkpoint weights and runtime libraries are not newly pinned here. No unsafe SSH, GPU, inter-PC execution or UNKNOWN replay is authorized by this change.

Three focused Rust binary tests passed debug and release, including same-length and reordered prompts, invalid vocabulary, and the plain/chat EOS distinction; targeted Clippy passed. An independent Python struct/SHA256/JSON oracle reproduced the Rust digest and v6 plan vector. On PC1, 29 Python tests passed using the existing Strata venv and observed tokenizer, including correct digest, altered/missing digest refusal, and old receipt compatibility. No model generation was run with this change, so R503 remains the latest real generation proof.
