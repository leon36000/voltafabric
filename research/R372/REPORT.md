Correction to the earlier proposed sentinel hypothesis: `expert_pool_dispatch_multi` receives normal expert IDs, rejects negative IDs, and uses an independently built per-entry `kind`/GPU plan to select CPU, VRAM, PCIe or peer work (`src/core/expert_source.cpp`, roughly lines 3140–3320). Remote helper work can also claim rows. A negative expert ID is not an adequate way to encode a GPU hit here.

`admit_mixed_pool_f64` accepts an explicit per-slot external ownership decision, validates the entire original route, stamp, shape and finite inputs, then creates bounded one-slot synthetic Session tokens for misses and retains their original slot positions. It preserves expert IDs, input rows and supplied weights; the unweighted Session path does not apply them. All-external batches need no Session invocation. `write_misses` stages and checks all FP32 conversions first, then updates only miss rows; external rows are not initialized or modified. The caller must guarantee exclusive writes and establish correct external-row initialization and completion.

This code does NOT authenticate the supplied ownership mask or bind it to Strata's actual GPU/PCIe/peer/helper plan. It is not wired to the void callback, does not launch or coordinate GPU work, and does not establish numerical parity with IQ3. Expanding misses can duplicate activation rows and changes Session token indices; mapping back is required and no speed claim is made. Process-local identity is not a durable lease or proof of exactly-once execution.
