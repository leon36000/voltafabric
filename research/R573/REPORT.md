# R573 — preflight first-position per-rank headroom

The SC117 prefill coordinator already checked the global budget against all 48 layers of seeded experts and the worst-case admission headroom. It also checked that each rank can hold its own seeds. However, with explicit per-rank caps it did not check before startup whether a single rank had enough remaining space for the first-position headroom required by the existing eviction policy. Since no position is committed yet, that policy cannot evict at position zero; a known-insufficient configuration could therefore start workers and consume the remote namespace before refusing.

The coordinator now rejects that configuration before computing an executable plan, consuming a namespace or starting workers. It checks overflow, requires every rank to hold its seeds and requires one rank to hold seeds plus first headroom. This preserves the existing conservative single-rank headroom rule; it does not establish that all future placements will succeed, guarantee peak RSS, or add remote or GPU support. No external code is copied.

Independent Python parsing of the 48-layer SC117 index computed 98,227,200 bytes of seeds per rank, 982,272,000 bytes of single-position worst-case headroom and 1,964,544,000 bytes for two positions. The Rust tests independently sum the indexed spans for experts 0 and 1, exercise exact boundaries, insufficient rank seeds, empty limits and overflow. Eleven coordinator tests passed in both debug and release. Clippy passed with the existing dead_code allowance and rustfmt passed. The first test attempt lacked VF_GGML_NATIVE_BUILD and failed in the build script; it was rerun against the existing isolated native build. No model execution, remote worker, GPU or R53 reservation was launched for this change.
