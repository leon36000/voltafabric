# R515 — refuse unbound generation receipts by default

Parent GitLab R514 e3f4c9f7cb40929ef5ffbf52ab28f48bec822d29. Previously `run_prompt` accepted a successful legacy or missing `plan_id` without requiring the token digest; stripping the plan field from a current receipt therefore bypassed that check. The library now defaults to requiring an r512 plan ID followed by exactly 64 lowercase hexadecimal characters and the SHA256 of the actual little-endian prompt token IDs before decoding or returning text. The CLI explicitly requests this strict mode. An explicit `require_bound_plan=False` remains for historical library fixtures; it is not a safe default for current generation. New plan versions must update this allowlist deliberately.

The checks establish receipt completeness and prompt consistency only. They do not independently reconstruct or authenticate the plan digest, authenticate the worker, checkpoint, host or external lease, and they do not make a compromised engine trustworthy. Existing caller responsibilities and no-replay rules remain. This is VoltaFabric glue around the existing Strata tokenizer adapter, not copied donor code.

On PC1 the real existing Strata virtualenv and observed tokenizer pack ran 30 unit tests with no skips. New tests refuse absent, unknown, uppercase, short and non-string plan IDs and absent or wrong token hashes; they accept a current-shaped plan and correct hash. Separate verify_real_receipt.py checks the original R514 result bytes against their published SHA256, reuses its retained receipt and real tokenizer without starting an engine, accepts `Hello`, and rejects altered plans and a missing digest. No GPU, worker, network worker, fresh generation or consumed claim replay occurred. PC1 scope was 512 MiB, no swap, 16 tasks, one CPU, nice 10; no worker remained after testing.
