# R602 — admission dynamique réelle et réduction scalaire vérifiée

Un essai synthétique local neuf traverse la vraie méthode `Owners::ensure`, la source d'experts avec comparaison des tranches, deux sessions et deux processus `vf-rank-session` CPU scalaires vérifiés par SHA-256. Après réservation d'un batch dans un registre local vide, l'expert manquant est admis sur le rang 2, puis les experts sélectionnés sur les deux rangs produisent une collecte complète non nulle. Les deux workers confirment leur fermeture après une exécution chacun.

Les experts utilisent intentionnellement les mêmes octets synthétiques non nuls : ce cas vérifie l'admission, l'identité, l'ordre et la réduction, pas la diversité des poids ni une génération de modèle. Le test compare chaque résultat du Collector à la référence scalaire locale convertie en f32 puis FP16. Le vérificateur Python effectue indépendamment ces conversions et la somme f64 pondérée : les 2 560 sorties correspondent bit à bit, SHA-256 `c40a50b7caf81b46c509f9d6a2f0449816ca29366a162df0a571fb51960cea46`. La référence des produits d'experts utilise le même code scalaire GGML que les workers ; elle n'est donc pas un oracle indépendant de ce calcul.

Le plan externe SHA-256 `dc84f1858455c5c4b0d9a12dcc69a1c84e7314338e5247e6528ba48a24856e6e` lie les sources, exécutables, index et runner à une identité neuve. Le marqueur de soumission exclusif a été synchronisé avant l'unique essai. Le seul claim, ses octets et son hash sont conservés dans `CLAIMS.json` avec le statut `RESERVED_UNKNOWN_NO_REPLAY` ; le vérificateur reconstruit aussi son identité. Les deux fichiers f64 publiés sont entièrement synthétiques. Aucun ancien UNKNOWN n'a été rejoué.

Le scope CPU est limité à un cœur, 1 Gio de mémoire, zéro swap et 32 tâches. Aucun GPU, réseau worker, registre R53 ou lease partagée n'a été utilisé. La suite de bibliothèque passe en debug et release (148 réussites, 8 ignorés chacune, dont les essais à plan explicite). Clippy passe avec l'avertissement historique `dead_code` autorisé ; rustfmt ciblé passe. La génération complète, l'authentification du plan et la qualification inter-PC restent ouvertes.
