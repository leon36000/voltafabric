# R489 — fail-closed memory check for SSH CPU workers

Parent GitLab R488 commit d2460fb3a73d8157c76b3209ff928921d50279be. The CPU rank-session binary now accepts one explicit `--guarded-remote` mode. Before emitting HELLO or loading any model data, it reads local `/proc/meminfo` and requires at least 2.25 GiB MemAvailable and 1 GiB SwapFree. Missing, duplicated, malformed or overflowed metrics refuse. SSH endpoints constructed by the SC117 prefill binary now pass this fixed flag; ordinary local sessions still use no arguments. Because the flag is included in endpoint argv, it changes the already configuration-bound plan digest for SSH; `verify_plan.py` independently confirms the new test vector.

The two memory thresholds follow the prior CPU-only single-owner resource preflight in `adapters/resource_admission.py` and the recovered R315 cross-host worker. This is an adaptation of VoltaFabric's own resource guard, not code imported from an engine. It is only a fresh snapshot: it does not reserve RAM or swap, check disk, predict the aggregate needs of 48 workers, pin the remote executable or host key, enforce R53, or replace any external fleet/hardware admission. A different executable could ignore the flag; externally verified binary and host identity remain required. SSH may not be used merely because this guard passes.

Both binary unit suites passed in debug and release; targeted Clippy passed. Guard tests cover exact floors, just-below floors, missing/duplicate values, wrong units, signs and numeric overflow. A direct invocation on PC6 with approximately 135168 bytes swap free exited 2 with the fixed refusal and zero stdout, before HELLO. This was a local resource refusal, not an inter-PC test. A fresh isolated CPU test using two real local workers and synthetic weights passed with the no-argument compatibility path; nine associated claims are preserved in CLAIMS.json and verified by verify_claims.py. They remain RESERVED_UNKNOWN_NO_REPLAY. No GPU, SSH worker, production service change or consumed claim replay was used.
