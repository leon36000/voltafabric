# R183 — chemin d'expert partagé à la frontière CPU

Le wheel 1Cat 1.2.2 épinglé contient `SharedExperts.apply` : cette méthode exécute le module partagé seulement lorsque l'ordre demandé correspond à l'ordre choisi et conserve son résultat séparément pour le runner. Le runner déclenche les ordres NO_OVERLAP et MULTI_STREAM_OVERLAPPED ailleurs, puis lit la sortie partagée. Le patch Skinny appelle l'ordre MK_INTERNAL_OVERLAPPED depuis la méthode des experts routés. Il serait donc incorrect d'additionner systématiquement la sortie partagée dans le Collector ou de l'appeler sans respecter l'ordre.

`shared_hook.py` adapte le pont CPU R182 : après validation, il délègue l'ordre interne à l'objet partagé et laisse au runner la propriété et la combinaison de sa sortie, tandis que les routes et coefficients suivent la session Rust. L'ordre est injecté par le futur runtime : aucune classe vLLM n'est simulée dans le code du hook.

Deux tests CPU réussissent : le premier utilise la vraie méthode `SharedExperts.apply` extraite par AST du fichier wheel SHA256 `e7504952e81b45ee69e4be5edce5f73b06186b6b309e3acd9c27bb6fe8109ee4`, une couche partagée CPU de test et deux appels à la vraie session Rust et ses propriétaires ; les sorties partagées sont produites une fois par appel et restent distinctes des 2 048 valeurs routées, qui concordent avec R158. Run `r181-539e3f7d9d7d4a82a15d6905a5add0f2`, registre `ledger/4fdaaf3e0ab08e150805a355c7ea33d83ad6e4dea894f93752aeff1bfc44298b`. Le second vérifie que les autres ordres n'exécutent pas la couche lors de l'appel interne. Commande : `source/.work/a92-cpu-venv/bin/python -B -W error::ResourceWarning research/R183/test_shared.py`, avec le chemin absolu de Python : exit 0, 2 tests.

Limites : l'objet partagé de test est artificiel et l'AST n'importe pas le vrai runtime ; pas de test de runner complet, multi-stream, exceptions inter-processus, modèle, GPU, réseau ni génération. Ce prototype n'affirme pas que la combinaison finale partagée/routée est qualifiée. Le fichier donneur inclus conserve ses mentions Apache-2.0 et copyright vLLM. Prochaine étape : vérifier 1Cat réel après réception R178, puis tester le runner et l'ordre réellement choisi pour un modèle compatible.
