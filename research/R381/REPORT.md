# R381 — Native residents through routing and the FP16 Collector

Parent: fb16f7449947b2dfa0c06efa258c1a1909ceb701. `native_ggml_cpu::Fleet` joins the R380 native Rust residents to the existing RoutingProblem, dispatch and ordinary Rust Collector in one process. It checks owner rank/expert/local and model/layer/epoch, bounds rank CPU work, associates successful output with the complete stamp and attempt, accepts only increasing attempts and rejects a repeated batch identity during the fleet lifetime. It captures run/plan scope on first execution. All owner results are staged through the Collector: unweighted FP32 is rounded to finite FP16 and decoded to f64, and the collector applies the original weights once in slot order. A failure after work starts makes the fleet terminal and exposes no partial result.

The guard is process-local and is lost on restart; it is not the durable R53 ledger, a lease, exactly-once execution or the Session wire protocol. Ranks in the test are logical identities of two owners within one process, not separate machines. Actual model/index hashes must come from a trusted manifest. The input and weights used in tests are synthetic native-format blocks; no real model payload was read.

Feature-enabled CPU tests passed four cases in debug and release. The fleet test loaded two distinct synthetic expert identities, compared all Collector values with explicit FP16 round/decode and weighted arithmetic, checked a stale epoch is refused before execution, rejected replay and non-increasing attempt, and verified an FP16 overflow yields no output and terminalizes the fleet. Its GGML numerical reference shares the provider and is not a model-level independent oracle; R379 separately compares GGML dot results to scalar dequantized arithmetic for synthetic rows. Strict offline feature-enabled all-target Clippy, format and `git diff --check` passed. No GPU/inter-PC operation or consumed UNKNOWN replay.

Next: implement an explicit native-format Session worker and admission/receipt path backed by durable identities, retain real weights without per-batch reload, and test process failure/no-partial-output before attempting a real checkpoint under resource gates. Full model generation remains unqualified.
