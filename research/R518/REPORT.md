# R518 — extend the bounded CPU generation window to 64 positions

Parent GitLab R517 d173aea4d4c8a05ebb68b7203729f8437529d6d4. The experimental SC117 CPU prefill and tokenizer now accept at most 64 prompt tokens and at most 64 generated tokens, subject to prompt length + maximum generation - 1 <= 64 input positions. Invalid combinations still refuse before workers. The cache uses the existing bounded QSA implementation; this does not add long-context sparse attention or claim 64-token real-model quality. This is VoltaFabric code around the existing traced Strata tokenizer and GGML provider, not code copied from a donor.

The R486 independent conservative receipt calculation was adapted to 63 eviction-bearing positions (at most 768 each), 64 positions of up to 48 x 10 admissions, 1024-byte event allowance, 128-byte admission allowance and 1 MiB fixed-field allowance. It yields 54,525,952 bytes under the new 64 MiB stdout capture limit. The formula is an upper bound conditional on those existing engine limits and the fixed-field allowance, not a measurement of process RSS or proof of a complete hardware admission; JSON parsing and Rust serialization allocate additional memory. Stderr remains capped at 64 KiB. All resource, identity, shared-lease and UNKNOWN rules remain in force.

The worker plan descriptor is now v9 with r518 prefix so that the expanded execution contract is not conflated with R512. The independently reconstructed test vector matches Rust. The Python strict path accepts r512 and r518 for backwards compatibility and still requires prompt digest; prepared plans and explicit expected-plan checks accept both versions. Any SHA-shaped plan is not independently authenticated by the wrapper.

Rust binary tests passed in debug and release, including 64 prompt + one generated token, one prompt + 64 generated tokens, and refusal of 65 or combined 65 positions. Targeted Clippy and rustfmt passed. On PC1, 33 tokenizer/adapter/chat tests passed with the observed tokenizer; synthetic receipts cover 64 generated tokens, incomplete output and boundary refusal. The preserved R514 real receipt is still accepted without launching an engine. No 64-position model run, GPU, SSH worker or replay was performed here; only the R514 shorter real generation is qualified. PC6 swap remains below the 1 GiB inter-PC gate.
