# R567 — bounded layer-major CPU prefill

Adds qualification-gated `Segment::advance_token_batch_with_source`, preflighting tokens, dimensions, cursor, each layer's attention position and QSA capacity before any claim. It runs each layer over the entire position group, reuses the reservation-bound GDN/PLE or QSA batch paths, and reserves each layer under the same position/attempt with the layer identity. Intermediate residuals remain private. If a later layer fails, earlier layer states may already have advanced; the segment is terminal and returns no partial output. It does not promise rollback of earlier layers. There is no eviction during a batch.

One bounded PC1 CPU run used real SC117 token embeddings for supplied IDs 42 and 73, layers 0 and 1 including PLE, 32 dynamically admitted expert payloads plus four seeds, and four guarded local rank workers. The two final residual hashes match the historical R453 sequential run exactly. Historical R453 independently checked PLE numerics with NumPy; the present full two-layer comparison is not a new independent oracle. In a distinct fresh fault run, layer 0 completed and layer 1 hit the expert budget after one admission; no result escaped, the segment remained poisoned at its initial public position and refused reuse, and PLE/GDN state for layer 1 remained unadvanced. Worker receipts show one execution per layer-0 worker and zero per layer-1 worker in that fault. Four new local claim receipts remain RESERVED_UNKNOWN_NO_REPLAY and are included.

The actual diagnostic was bounded to 4 GiB RAM, no swap and 100% CPU quota. Native qualification-feature Clippy passed with an allowance for the pre-existing trace-only dead_code; debug and release library tests each passed 134 with five ignored; rustfmt passed. The multi-layer QSA branch is implemented by calling the existing R559 QSA batch path but was not executed in this two-GDN-layer test. This is local CPU only, not full-model prefill or GPU/inter-PC/generation qualification.
