# R569 — headroom between layer-major CPU batches

Adds qualification-gated headroom for the multi-layer token batch path. A shared preflight checks every token, input, layer position and QSA capacity before planning or submitting any eviction. The existing conservative policy protects each layer's previous batch route union and evicts only acknowledged eligible residents on active ranks, preserving at least one resident per rank. Headroom counts expert payload bytes, not process RSS and not a prediction of future routes. Eviction is between batches, never inside a batch; an uncertain eviction leaves the segment poisoned.

On PC1, two distinct local CPU segment runs each processed two consecutive batches of real token embeddings 42 and 73 across layers 0–3, including PLE and QSA. Both loaded 106 route-selected experts dynamically. The headroom run evicted two unselected layer-0 seed experts between batches, freeing 4,352,000 payload bytes, then produced two second-batch residual hashes identical bit for bit to the no-eviction baseline. Before that, an invalid token plus a headroom request was rejected with cursor and source accounting unchanged. Both cases had eight guarded local workers, each executed twice and exited cleanly. This is a same-implementation CPU comparison, not independent model parity or a performance test.

The run was limited to 6 GiB, zero swap and 100% CPU quota; no GPU or inter-PC workers. Eighteen new local execution and eviction claims remain RESERVED_UNKNOWN_NO_REPLAY and are included. The native qualification-feature library tests passed 134 with five ignored in both debug and release; Clippy passed with the pre-existing trace-only dead_code allowance; rustfmt passed.

This establishes only a four-layer, four-position local diagnostic. It does not establish sufficient headroom for arbitrary unknown routes, full 48-layer prefill, complete generation or distributed execution. Next extend the prefill driver toward all layers and output head, with explicit bounded placement and independent numerical checks; keep UNKNOWN claims non-replayable.
