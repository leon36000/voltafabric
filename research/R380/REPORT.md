# R380 — Verified native expert into a Rust CPU resident

Parent: 10853338ee0f0caffdab6925eb1d47cc0f9eb732. This connects R378's digest-checked native expert bytes to R379's actual pinned GGML CPU computation, in-process. `native_ggml_cpu::Resident::load` checks the supplied layout's index digest, layer/expert/span, bounded blob length, SHA-256 and nonempty model revision before creating a native resident. Its binding retains rank, local expert and epoch. These caller-supplied values and expected hashes must come from a trusted manifest: this is not an authenticated model or a durable distributed lease. The optional `native-ggml-cpu` feature preserves the default build and separates native GGML formats from QPN2/MXFP4.

A narrow C ABI owns one native copy of the weights. The separate `vf-ggml-native-ffi` crate owns and destroys its opaque pointer; Rust's core continues to forbid unsafe code. Calls require exclusive mutable access and return unweighted FP32 rows, with no routing coefficient applied. The native build directory is caller-supplied and must itself be a verified, isolated build of the pinned donor; the Rust feature does not independently attest the compiled archives.

CPU tests: feature-enabled `strata_native_provider` passed three tests in debug and release, including a nonzero synthetic expert with a Python-generated hash, two identical forwards on one resident, rejection of a mutated payload and incorrect expert identity, and nonfinite input refusal. The C++ donor test passed all seven SC117 format pairs, with a resident-copy test confirming later mutation of the original buffer does not alter either forward. The default `strata_native_layout` test passed all three cases. Feature-enabled strict offline all-target Clippy, format checks and `git diff --check` passed. C++ is built from the pinned MIT GGML and Strata references documented in R379; no actual SC117 weights, GPU, inter-PC run or consumed UNKNOWN were used.

Not yet connected to a Rust Session, Collector, persistent multi-expert worker or actual checkpoint; no full generation, hardware parity or performance claim. Next create a separately identified native-format worker/session boundary with resident loading and atomic receipts, not a disguised MXFP4 or QPN2 artifact, then compare actual experts to an independent oracle subject to admissions.
