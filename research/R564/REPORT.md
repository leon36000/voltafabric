# R564 — resolve R563 broad CPU test failures

R563's 10 library failures were reproduced, then traced to an incomplete isolated worktree: `.runs`, a checkpoint fixture and the fake peer script were missing. A first attempt to repair this in a new directory reused the old target directory; Cargo reused a test executable compiled with the previous CARGO_MANIFEST_DIR. Inspection of that binary's strings shows eight references to `/home/pc1/NAOS/vf-r563-work`, explaining why adding the files in the new directory did not change the failures. This is a test setup and artifact-reuse finding, not evidence that any particular production path was defective.

A fresh `/home/pc1/NAOS/vf-r564-work` was prepared with the required small fixture and peer scripts, its own `.runs`, temporary and Cargo target directories, and the previously verified CPU native libraries. Both affected source files have identical SHA-256 to the R563 source on PC6 (bound layer 3b772ad203a692976205b473a67507471ca9b057f054160e85b701ee7e421405; GDN stage 81f51077add765ed7b440348ec122897ddce82032329f39f26271a1862b8d4a0). These are the library tests, not every integration test or a full model qualification.

The tests ran in a PC1 CPU scope with 2 GiB RAM limit, zero swap and 200% CPU quota. The synthetic test ledgers have unique fresh paths; none of R563's six UNKNOWN claims was replayed.
