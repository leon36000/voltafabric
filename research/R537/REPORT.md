# R537 — live QSA trace checked over 92 generation positions

The experimental SC117 CPU generator now has an explicit local-only `VF_QSA_TRACE_LAYER=3` mode. It binds the mode and its fixed layout to a distinct r537 plan derived from the ordinary r531 plan; unsupported layers, nonlocal workers and a combined input-position limit over 96 are refused before execution. The layer-3 trace is captured through R536's post-commit boundary, checked against run/model/plan/layer/batch/epoch/attempt for each position, retained privately and emitted only after all workers close successfully. A failed/truncated receipt is rejected by the tokenizer adapter. The adapter checks plan, metadata, size, canonical base64 and SHA256 before releasing decoded output.

A fresh local PC1 run processed the same 73-token prompt as R534, produced 20 tokens ending in EOS and the same answer: `Hi! 👋 That’s quite a lot of greetings! How can I help you today?`. All 92 input tokens, embeddings and final-layer output hashes, plus all 20 output tokens and logits hashes, exactly match R534. All 96 workers closed; stderr was empty. The independent ledger verifier checks the 20,709 claims, including 16,293 evictions and rank accounting. All 6,198 admitted distinct experts match prior locally observed source slices from R534 and its ancestors; no additional source observations were required. All claims remain UNKNOWN and cannot be replayed.

R535's separately written NumPy oracle was run on the actual committed layer-3 trace from this generation. It checked all 92 positions against observed raw projections for weighted RMS, partial RoPE, FP16 KV caching, causal grouped attention, softmax and gating. Maximum absolute differences: query 9.5367431640625e-7, key 4.76837158203125e-7, attention 1.5078360127152024e-7, each below the predeclared 1e-5 tolerance. This independently checks that boundary, but consumes actual projection outputs, shares the locally observed weights/quantizers, and does not independently validate projections, other layers or full-model numerical parity. It is not GPU, remote-worker, RDMA or distributed qualification. The R428 expert-255 scalar discrepancy remains open.
