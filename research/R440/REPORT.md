# R440 — route-driven admission of missing local CPU experts

Parent R439 `ad6b2bf371f98810df2906d8509f8aa0723c5989`. `Segment::advance_with_source` offers an explicit opt-in missing-expert source. After the real QSA or GDN gate selects its experts, and after the layer's durable local reservation, it asks the source only for experts absent from the current registry. The supplied binding must match model, layer, epoch and selected expert; an existing rank session then independently checks index and payload digests and appends the resident. Registry and physical order change only after the matching worker acknowledgement. Existing residents remain in place. Any error leaves the segment poisoned and its claim consumed, so an uncertain load or worker attempt cannot be blindly retried.

The source chooses placement, supplies an independently trusted digest and enforces its own overall memory budget. Existing worker per-rank count/byte bounds still apply. This API does not implement eviction, cross-machine placement, authenticated model provenance, R53 leasing, GPU execution, or dynamic creation of empty rank sessions. The diagnostic source's rank limit was ten resident experts per rank and its digests were observed from the local pack, not authenticated externally.

One fresh PC1 CPU execution advanced layers 3 QSA and 4 GDN through two different synthetic positions. Each layer started with only two previously selected seed experts, one per local rank. The actual routes requested 29 additional distinct experts during the two positions; subsequent calls reused residents. The four rank workers each executed twice and closed normally. Both final outputs compared equal as f32 values to a separately staged in-process preview sharing the same native provider and Rust completion implementation; this is integration evidence, not independent full-model numerical parity. `success/RESULT.json` SHA `2d33d755254fb7d8dd6b791d3df3dbd16a30a55c1aec53fa053660ac0e482f7d` records every source call, selection, binding digest and output hash. `success/WEIGHTS.json` SHA `4535d10e5c8bfb25db984716132ee80e1c711a75e837eb3eaa43f5cae3b51942` verifies all 33 observed seed/loaded expert blobs against their GGUF slices and confirms no duplicate source call. Those local matches do not authenticate the publisher or checkpoint.

A second fresh run deliberately refused a missing expert in layer 4 after layer 3 had completed. `fault/RESULT.json` SHA `090d89ae05ac141d46ee3273fac19b98f039705cac7e2de2dd88ffd607a02353` records `SOURCE_FAULT`, no returned partial output, a poisoned segment, a refused subsequent advance and clean worker shutdown with execution counts `[0,0,1,1]`. Both runs' copied claims remain `RESERVED_UNKNOWN_NO_REPLAY`; they must not be replayed. No GPU or inter-PC worker ran; local native ledger claims are not R53 leases.

Four focused segment tests passed debug and release, including refusal of a source returning another expert and skipping a source for an already resident expert. Three append-owner regression tests passed debug; default-feature `a52_session` passed 28 tests. Native-feature Clippy with warnings denied and formatting passed for the implementation and diagnostics. The actual provider is the MIT GGML/llama.cpp–Strata boundary recorded in earlier reports, not a guarantee of donor engine quality.
