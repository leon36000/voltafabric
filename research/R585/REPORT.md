# R585 — Require stable expert rank for SSH CPU workers

The SC117 prefill coordinator previously allowed SSH workers while sticky expert rank affinity was off. R575 shows that the same actual expert and input can differ between PC1 and PC6 producer builds. The coordinator now rejects SSH configuration without `VF_EXPERT_RANK_AFFINITY=sticky` before opening model files, consuming R53 namespace reservations or launching workers. The existing sticky policy retains each `(layer, expert)` on its original rank after eviction and refuses readmission if that rank cannot fit it. Local-only behavior remains unchanged; a valid SSH/sticky plan already binds the affinity policy in the existing r576 plan domain.

This restriction prevents silent reallocation of an already seen expert between ranks in this coordinator. It does not establish numerical equivalence across ranks, authenticate libraries, make a heterogeneous placement safe, replace an external numerical contract or authorize distributed execution. The authoritative shared R53 ledger, genuine shared lease and other fresh hardware/network admissions remain required. Old SSH non-sticky configurations now fail intentionally; old UNKNOWN claims remain consumed.

Fourteen coordinator unit tests passed in debug and release; targeted Clippy passed with the existing dead_code allowance, and rustfmt passed. `verify_guard.py` runs the actual debug coordinator in plan-only mode with a syntactically shaped inert test host key and nonexistent model paths: non-sticky SSH is refused by the new guard; sticky SSH proceeds only to the existing missing-shared-lease refusal. No SSH connection, worker, GPU, live R53 claim, or model inference occurred. The first test build intentionally exposed the missing guard symbol before implementation; it did not run a behavioral test until the guard existed.
