# R182 — délais et traces locales pour la session persistante CPU

`durable_hook.py` relie la méthode MoE extraite à la session R181. Avant tout lancement il revendique exclusivement une identité run/modèle/plan/couche/epoch dans un répertoire local, puis écrit chaque identité de batch avant envoi avec fsync. Les entrées et sorties des pipes sont non bloquantes et bornées par une échéance ; en cas d'incertitude le hook devient terminal sans rejouer ni tuer automatiquement un processus à l'issue inconnue. Un résultat n'est rendu qu'après stockage et fsync de ses octets FP16 et d'un reçu contenant leur SHA256 et le numéro attempt réellement attribué par Rust. L'identité revendiquée ne peut pas être réouverte dans ce même registre local.

Commande : `source/.work/a92-cpu-venv/bin/python -B -W error::ResourceWarning research/R182/test_durable.py`, avec le chemin absolu de Python depuis le dépôt : 2 tests réussis. Le premier fait passer deux appels donneur réels par la session Rust et les deux propriétaires persistants CPU R181, compare aux deux sorties de référence R158, vérifie les hashes et refuse la réouverture du même run. Run `r181-af9b160ce3a44a80b7eeb73fc7753c34`, registre `ledger/e7428c880290b8ed2143481c99c8af23aa82dbb717c1446ab72686a65f176d80`.

Le second lance uniquement un petit processus factice qui confirme l'initialisation puis temporise : l'échéance est atteinte, la revendication reste sans reçu de succès, et un second appel ainsi que la réouverture du run sont refusés. Le processus factice se termine avec code 0 et a été attendu, donc ce cas simulé est réconcilié ; run consommé `r181-73cc8723f2d54e829d1b1049300c5edb`, registre `ledger/380158c513076a102ed9da6c75eee781fade8b4a19296a1400c64792b336b253`. Les anciens tests et leurs traces restent conservés.

Limites : le registre est local et ne constitue pas une lease partagée ; aucune reprise après crash n'est réalisée et un run inconnu nécessite réconciliation du PID et des sorties. Le hook dépend d'un prototype CPU restreint à un token, deux routes et des propriétaires locaux avec fournisseur de test. Il n'importe pas le vrai runtime 1Cat, ne traite pas les experts partagés et n'est ni une validation GPU, ni une génération ou distribution réelle. Aucun résultat de performance.
