# R404 — real token embedding and first attention-side hyperconnection

`hyperconnection_cpu::read` implements a bounded CPU reference for the Strata fb58 hyperconnection read, based on the MIT donor's `include/strata/kernels/gr.hpp` and `src/kernels/cuda/gr.cu`: per-stream RMS normalization, BF16 rounded activations, down projection and SiLU scaled by the number of streams, BF16 bottleneck, up projection, sigmoid-gated mean, and injection projection. It uses scalar f64 dot accumulation and is explicitly not a claim of CUDA bit parity. It validates shapes, finite values and bounded allocation before returning a complete output. The local diagnostic reads the four observed layer-0 attention-side tensors by fixed SC117 spans and operator-supplied SHA-256 values; it is not a generic checkpoint loader.

The actual SC117 first GGUF shard's pinned donor header reader reported `token_embd.weight` as IQ4_XS, shape [2560,248320], tensor start 545644544, row size 1360 bytes. The index's native placeholder is not evidence of Q8_0. `sc117_embedding.cpp` explicitly decodes token ID 42 (vocabulary token `K`) with the existing local GGML IQ4_XS decoder, producing a 10240-byte FP32 embedding with SHA-256 `ae94a5f1a2e54b8f2e9719409640badfbba583e83ae82ad66987da58ee64ae31`. GGML decoding is not independent of GGML and fixed metadata is specific to this observed checkpoint; file identity is not publisher-authenticated.

On PC1, the real token embedding was broadcast to four residual streams and processed with actual attention-side norm, down, up and injection weights (observed SHA-256, in that order: `a2be4ca661ebebcffddfa452dab947242d92a1f71f14a5392110be41e55398a3`, `0cf47e5bf283e8974c8d24bb3dfc1aef536b7d0daff9ac69f9ae8f214e6aed6a`, `6e87eb16e95e4e24cb83f3852d4200bdff7da87d8e8989022fe8012b88c2f978`, `97548dcae39b501c2958bb607d3954b484fce8abe4ae758e8bb09e988d37abc9`). Descriptor metadata remained stable during the bounded observation. A separate NumPy implementation matched the 2560 mixed outputs within 2.384185791015625e-07 absolute and all four injection values exactly; tolerance was 1e-5. This is before attention, not the post-attention router input, a full model layer or token generation.

Two CPU unit tests cover deterministic normalization, stream injection, bad shapes and nonfinite/overflow rejection; strict clippy and formatting pass. The embedding decoder and diagnostic ran locally on PC1 CPU with isolated files under NAOS; no GPU, distributed worker, service modification or UNKNOWN replay occurred. The NumPy reference shares the described arithmetic semantics but not Rust code.
