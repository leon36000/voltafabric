# R390 — opt-in CPU-only Strata source handoff candidate

`pool_cpu_only` adapts the pinned multi-pool arguments to the R389 C++ binary client. A per-layer context assigns monotonically increasing batches, stages all unweighted FP32 rows, and latches any failure; it never writes partial rows or automatically retries. An end-to-end synthetic local test exercises the C++ hook, Rust coordinator and two persistent CPU rank-session children over Unix sockets. Two distinct batches match direct native-provider FP32 bits; an invalid layer latches failure and leaves the destination untouched. A separate adversarial C++ socket test injects duplicate returned slots, checks the hook fails closed without modifying output, and checks a later call is refused. C++ tests pass in Debug and Release; the local Rust integration passes with both C++ client and hook test paths explicitly supplied.

`strata-fb58-cpu-hook.patch` is a candidate against clean Strata fb58e0dbc8399662c0e47c76578c6e878b14f6cf (MIT), not applied to the donor or a live service. It adds opt-in hook fields at the actual `expert_pool_dispatch_multi` site, restricts the selected SC117 experts to CPU-only (rejecting resident GPU hits, PCIe, peer/helper, lookahead and foresight), and forwards callback failure as a boolean to the four CUDA verifier call sites. On failure it requests the existing bounded wait release and returns an error instead of reporting output; a stream-query error is no longer called a successful drain. The source has not been linked or executed on GPU, and neither GPU drain nor mixed owners are qualified. The patch does not instantiate or configure hook contexts and is not a full model integration.

The generator checks the exact clean donor and deterministic patch; `git apply --check` passes. `check_reference_patch.py` applies it only to a private five-file overlay and runs syntax-only compilation of the actual patched expert source, verifier, generate source and callback signature. On AArch64 the two x86 intrinsics are parsing stubs, never executed; this is not an x86 build or runtime proof. R389's local durable ledger and all hardware/UNKNOWN gates remain required. Real checkpoint identity, per-layer coordinator lifecycle, actual model outputs, external synchronization, GPU verification and complete generation remain open.
