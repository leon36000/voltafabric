# R379 — GGML native expert CPU component

Parent: 1132bddec987891a03efcf259af4750453d84917. Strata donor fb58e0dbc8399662c0e47c76578c6e878b14f6cf pins llama.cpp/ggml 3cf03257f219afbe7334045ff7c6a06ac68c627d (GGML 0.24.0). Both are MIT licensed; their notices are included with the adapter. GGML is an external pinned source dependency and is not included in the GitLab commit.

`adapters/native_ggml` implements an isolated CPU single-token native expert calculation using GGML's actual activation quantizers and dot traits and Strata's gate/up–SiLU–down sequence. It admits SC117's four observed gate/up and two down type families, requires hidden 2560/intermediate 640 and exact packed length, rejects nonfinite input/intermediate/output, and stages output so ordinary refusals leave the caller buffer unchanged. It does not apply gate coefficients. The caller must authenticate and retain the weights and bind model/layer/expert identity; R378's verified reader is not yet connected to this C++ API.

A clean sparse checkout of the exact GGML commit (29 MiB) and an isolated CPU-only generic ARM64 release build were created under `.runs`; no GPU backend was enabled. All seven actual format pairings from the SC117 metadata passed synthetic nonzero packed-block tests. Each result was compared with scalar multiplication of dequantized rows/activations; Q8_K activation dequantization is explicit in the test, while weight dequantization and activation quantization use GGML and thus this is not fully independent of GGML. Wrong type, shape, nonfinite input and truncated blobs are refused without changing the output. CMake source revision/clean checks, `-Wall -Wextra -Werror` for the adapter, `ctest`, and `git diff --check` passed. No real expert payload, GPU, inter-PC test or UNKNOWN was used.

Not yet qualified: real checkpoint blobs or manifests; GGML CPU versus actual Strata optimized kernels and other hardware; numerical tolerances for a model; Rust Session and Collector integration; failure propagation across the C++ boundary; full generation and performance. Next connect an authenticated R378 blob to a resident process provider with exact identity/no-replay and compare a real expert to an independent oracle when resource gates allow.
