# R531 — bounded 128-position SC117 CPU window

The experimental SC117 CPU generator and Strata-tokenizer adapter now allow up to 128 prompt tokens and 128 predictions, provided `prompt length + requested predictions - 1 <= 128`. Combinations exceeding 128 are rejected before worker launch. The plan descriptor is v16/r531 so this changed contract cannot be confused with the prior 64-position version. Existing model formats and reduction contracts are unchanged.

The QSA CPU cache remains under its separately documented 2,051-cell identity-selection limit; no sparse selection or long-context GPU behavior is introduced. A synthetic causal-attention test advances 128 positions, compares the uniform-attention result at every position to an independently calculated mean and refuses position 129. This exercises cache behavior, not model-level parity. The tokenizer tests cover a 128-token prompt, 128 generated tokens, incomplete receipts and overflow rejection. They ran 36 tests on PC1 with the observed tokenizer and no skips.

The output capture bound rises from 64 to 128 MiB. `verify_bounds.py` conservatively calculates 108,789,760 bytes using the existing limits of 127 eviction-bearing positions, 768 evictions per position, 48 layers with at most ten admissions each per position, 1,024 bytes per eviction, 128 per admission and a 1 MiB fixed allowance. This is a conditional serialized-receipt bound, not a process RSS measurement: JSON generation and parsing can allocate additional memory. The external resource scope still governs execution.

Seven Rust coordinator tests and six QSA tests passed in both debug and release. `verify_vector.py` independently reconstructs the versioned plan. The real model has not yet been tested beyond 64 positions with this version; R519 verified 42 real positions under the previous version. No GPU, SSH worker, shared hardware reservation or consumed-claim replay occurred. Next perform a fresh, externally admitted local CPU run longer than 64 positions and compare available prior prefixes and expert source observations, then continue toward actual distributed execution only when the shared lease, R53, host identity and resource gates are satisfied.
