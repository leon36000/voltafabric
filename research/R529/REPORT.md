# R529 — bind and consume R53 namespaces before SSH worker launch

For SSH ranks, the v15/r529 SC117 plan now includes a caller-supplied R53 root path, device, inode, UID and base ID as well as the previously bound lease identity. Preparation requires the existing pinned private directory; it creates no reservation. Before weights or workers, the coordinator checks the exclusive inherited lease, opens that exact directory without following its final symlink, and requires both the base and `-duplicate-slot` records produced by the recovered R53 namespace tool. Both records must be private regular files, retain `RESERVED_UNKNOWN_NO_REPLAY`, and contain the exact plan ID and lease identity in their context.

After verification it exclusively creates, writes and fsyncs a separate `<base>-sc117-started.json` marker in the same directory and fsyncs the directory. A prior marker prevents a second launch. Any failed or interrupted marker creation, persistence or subsequent execution must be reconciled; neither R53 record nor marker grants permission to replay an UNKNOWN. The controller is responsible for externally reserving the base and suffix once with the required context before submission. This is not a replacement for fresh hardware/resource admission, a verified shared lock, host authentication or remote-process reconciliation.

On PC1, seven Rust binary tests passed in debug and release, and 36 Python tokenizer/adapter/chat tests passed with the observed tokenizer. A no-worker preflight used the actual recovered `namespace_ledger.py` (SHA256 `4ffce4c37cfd27213af9ab9cc31548641cc89d88179460fd41ed4fb9eac7f9fd`) with a fresh synthetic private R53 directory and synthetic exclusive lease. Missing reservations were refused without a marker; after the original R53 tool created both matching entries, the actual release coordinator created its marker and then refused the intentionally non-regular PLE source before any worker or native claim. Independent JSON/SHA256 reconstruction verifies the v15 plan and retained base, suffix and marker identities. Unit tests also refuse a partial reservation, mismatched plan and duplicate marker. These are synthetic records, not production reservations.
