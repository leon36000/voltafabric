# R592 — opt-in native scalar expert reference

Adds a separate C++ diagnostic library target, `vf_native_scalar_reference`, enabled only by `VF_BUILD_SCALAR_REFERENCE=ON`; it is not linked into the default worker or generation path. `scalar_reference_iq2s_iq4nl` accepts one observed SC117 expert in explicit GGML IQ2_S gate/up and IQ4_NL down format and returns 2,560 unweighted f64 values. It adapts the R590 diagnostic's scalar ordered double-dot calculation and the pinned MIT llama.cpp GGML `3cf03257f219afbe7334045ff7c6a06ac68c627d` quantizers/dequantizers. The caller still authenticates expert data and supplies the correct identity; this standalone diagnostic has no run/epoch or routing semantics and does not apply route coefficients. It is not the ordinary worker's FP16-decoded Collector contract.

The reference requires a little-endian IEEE host with round-to-nearest, rejects wrong shapes, nonfinite inputs/decoded weights/intermediates, nonzero subnormal inputs/intermediates and magnitudes above 1e12, and stages output until complete success. CMake requires GNU/Clang and disables contraction and fast math for this target. These restrictions make the examined domain explicit but do not prove cross-platform determinism, bound std::exp, authenticate a model or qualify GPU/distributed use.

New synthetic tests cover zero-output success and atomic rejection of malformed size, NaN/Inf, nonfinite weight scale and a non-default rounding mode; debug `-O0` and release CTest passed. An independently compiled diagnostic caller compared 48 nonzero expert/input cases on each of PC1 and PC6 against R591's retained scalar f64 captures, all 96 matching exactly. This is a separately implemented scalar comparison but shares GGML decoding/quantization with the reference; input corpus, layers and formats remain limited to R591. The CMake-built library also matched the retained expert-255 sample and rejected a deliberately corrupted expected capture with exit 5. No model worker, GPU, network execution, R53 lease or UNKNOWN replay was used. `PLAN.json` binds source, driver, inputs and binaries before the corpus runs; raw model-derived data stay local.

This adds an integration-ready reference and tests, not a production backend, a performance result, whole-model equivalence or a shared-lease solution. Next verify additional model formats/inputs and bind a numerical contract before any remote producer qualification; preserve all existing R53 and UNKNOWN protections.
