# R589 — compare scalar and vector threshold on PC1 and PC6

The R539 PC1 x86_64 witness had one Q8 intermediate code difference between scalar and vector gate/up calculations at index 541. A fresh local PC6 AArch64 diagnostic used the same R428 observed expert-255 slice and activation, pinned GGML revision `3cf03257f219afbe7334045ff7c6a06ac68c627d`, and the existing scalar-double-dot diagnostic adapted to read only that retained expert slice. It does not invoke a worker or create a reservation.

At index 541, scalar intermediate and block maximum are exactly the same recorded f32 values on both hosts: -0.056449014693498611 and 0.059493966400623322. Both scalar paths produce code -121. The PC1 vector path scaled to -120.49999237060547 and produced -120; the PC6 vector path scaled to -120.50001525878906 and produced -121. On PC6 the complete quantized intermediates had zero byte differences between the scalar and vector calculations, whereas PC1 R539 recorded one. PC6 still had a maximum scalar/vector intermediate difference of 1.49011612e-8. The separate PC6 scalar down projection matched its vector-provider output at the established tolerance for this one witness; it was not compared against a retained PC1 full scalar output.

This narrows the discrepancy to a build-dependent gate/up intermediate near a quantizer boundary, but does not prove ISA alone is responsible, that scalar calculations are fully portable across machines, or that any model-level tolerance is satisfied. Quantization and dequantization use the same pinned GGML code; the dot accumulation is an independent scalar-double computation. R428's original scalar failure on PC1 remains open. `verify.py` independently reconstructs float32 scaling and round-away-from-zero for the four recorded values and checks source and historical report hashes; it verifies recorded observations, not raw checkpoint provenance.

Both local probes ran with 512 MiB memory, zero swap, 50% CPU and 16 tasks; no GPU, network worker, hardware lease or UNKNOWN replay was used. `PLAN.json` binds the initial probe source preserved as `scalar_probe_initial.cpp`; `DETAIL_PLAN.json` binds the later `scalar_witness.cpp` and its explicit index-541 output. Raw model-derived bytes remain local. A possible canonical scalar path requires a defined cross-host arithmetic contract and independent multi-expert testing before any use in distributed generation.
