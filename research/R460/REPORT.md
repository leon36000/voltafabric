# R460 — checkpoint-bound Strata tokenizer adapter and R459 text

Parent R459 `a7985e5f3d621ece5ae820b010a1016dd2ce44ff`. VoltaFabric now includes an adapter around unmodified `tools/strata_tokenizer.py` and its GGUF reader from Strata commit `fb58e0dbc8399662c0e47c76578c6e878b14f6cf`, MIT license and copyright preserved in `adapters/strata_tokenizer/vendor/LICENSE`. The actual local donor files match that clean commit. The existing Python `regex` package version 2026.9.10 was used on PC1; the package is not vendored and other environments must supply a compatible version.

The adapter reads four caller-pinned, bounded regular files, verifies SHA256 and file identity across reads, validates the observed SC117 vocabulary geometry, merge uniqueness, Qwen35 type and EOS, then uses the donor's byte-level BPE. A strict incremental decoder keeps split UTF-8 sequences intact, stops at EOS and poisons itself on malformed bytes, out-of-range IDs or unexpected control/unsupported tokens. A receipt adapter validates the structure and autoregressive token handoff of an authenticated-by-caller R459-style receipt, limited to two positions, then returns text only after complete successful decoding. These checks do not authenticate the source model or the receipt, implement chat formatting, or qualify general sampling.

PC1's observed tokenizer pack was compared against the local first GGUF shard's metadata: all 248,320 vocabulary entries, 247,587 ordered merges, token types, model/pre type, special IDs, EOS and add-BOS policy matched. Five diverse UTF-8 strings round-tripped. For R459's actual receipt, supplied token 42 and generated IDs 3649 and 1277 decode to `Kıbr`; generated text alone is `ıbr`. The displayed sequence was stopped by the two-token limit, not EOS. A separate byte-alphabet reconstruction matched those three pieces. This is not evidence that a one-token prompt produces meaningful text, nor independent validation of model logits or every tokenizer case.

Five focused Python tests passed on PC1: split UTF-8, EOS and poisoned failure behavior, malformed IDs and controls, duplicate JSON keys, atomic receipt refusal, actual pack loading and wrong-digest refusal. The final metadata comparison ran under a 2 GiB, zero-swap CPU-only systemd scope with a 178.5 MiB reported peak. No model or hardware runner was executed; no UNKNOWN was replayed. Published and PC1 versions of the adapter, test, manifest and qualification script have identical SHA256s.
