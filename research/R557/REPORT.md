# R557 — atomic QSA layer batch with real experts

`RoutedBatch` binds the provisional QSA stage, the FFN router, shared-expert output and the Rust native Collector to one reserved batch identity. It computes all residuals before committing the QSA cache. Shared and collected results carry a private transaction marker; stale or cross-transaction producers are rejected. The caller owns the local ledger, admission, weight residency and the surrounding multi-layer transaction.

On PC1 CPU, two observed layer-3 input positions and their actual routes were run through QSA, FFN, shared expert and 17 digest-checked native GGML expert slices in two local guarded rank sessions. The two 10,240-element residuals matched the sequential `Routed` layer path bit for bit. All computed routes and activation hashes matched the R554 observed prefill specification. A malformed second position caused preparation to fail with an empty active cache. After actual expert collection, substituting a shared result from a different transaction was refused and both active caches stayed empty. Both workers closed cleanly. The six local claims remain RESERVED_UNKNOWN_NO_REPLAY. The separate initial successful run and its four claims are preserved too.

Native-feature library and qualification binary passed Clippy with warnings denied and `dead_code` allowed for the pre-existing trace-only struct; Rustfmt passed. The sequential comparison shares the same native kernels and is not an independent model oracle. This directly qualifies only a local CPU layer on two captured positions, not a fresh end-to-end batch prefill, GPU, or inter-PC transport. Dynamic owner admission and eviction are not yet wired into this batch boundary. GDN/PLE and model-level atomicity remain to be integrated; no performance claim is made.
