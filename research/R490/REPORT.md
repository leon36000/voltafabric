# R490 — negotiated raw FP32 activations for native GGML workers

Parent GitLab R489 commit c159b9995673f1fd980501e2e1f6bbc8764280d4. Native GGML EXEC previously encoded FP32 activations as JSON. This change adapts VoltaFabric's existing bounded raw-frame approach to a distinct native GGML capability: a JSON identity/dispatch header is followed by exact little-endian FP32 input bytes. New workers advertise `cpu_strata_sc117_ggml_input_raw_f32_v1`; the coordinator uses this only when advertised and otherwise sends the existing JSON request. The worker decodes to the same native request before executing. Output contracts remain unchanged: ordinary decoded-FP16 Collector accumulation and the separately selected unweighted-FP32 path are not conflated, and routing weights are not applied twice. There is no retry or JSON fallback after a transmission or uncertain result.

Metadata counts, byte lengths, finite values and maximum frames are checked before allocation or execution; a short or malformed body is refused and the session ends because the stream boundary is no longer reliable. A raw request counter is included in Traffic with serde default and omitted when zero, preserving old Traffic JSON, and the CPU prefill receipt records per-worker raw request counts. The counter reflects successfully transmitted requests, not network-level acknowledgement or throughput. This adaptation reuses the project's A55 framing concepts, not donor source code; the underlying GGML version/license provenance remains in R379.
