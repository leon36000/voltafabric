# R583 — Skip ranks with exhausted local identifiers

The SC117 admission planner formerly chose the least-loaded rank before computing the next local identifier. If that rank's maximum local identifier was `u32::MAX`, it returned an overflow error even when another otherwise eligible rank had a valid next identifier. A regression test demonstrated this failure before the change. Placement now excludes ranks lacking a representable next local identifier before ranking candidates, both with and without payload caps. Existing eligible-rank ranking is unchanged. If a sticky expert is pinned to an exhausted rank, it still fails rather than moving to another producer. If all candidates are exhausted or have insufficient budget, admission fails before append. This is an extreme identifier-exhaustion edge case, not a demonstrated performance improvement.

The regression test covers uncapped and capped selection, exhausted sticky rank refusal, and all-ranks-exhausted refusal. Library tests with the existing CPU-only native provider: 138 passed, six ignored, in both debug and release. After clarifying the error messages, seven targeted source tests passed and one explicitly planned-worker test was ignored. Clippy passed with dead_code allowed, and the touched file passed rustfmt. An initial attempt failed to link because an older local native library lacked prepared-input symbols; a separate CPU-only build from pinned llama.cpp GGML commit `3cf03257f219afbe7334045ff7c6a06ac68c627d` and the current bridge resolved the environment mismatch. No GPU or inter-PC workers were started and no UNKNOWN was replayed. This change does not establish whole-model numerical equivalence, live R53 reconciliation or a shared lease.
