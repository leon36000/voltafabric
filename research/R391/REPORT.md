# R391 — execute the candidate donor CPU branch against the native bridge

The R390 verification script now optionally extracts the exact opt-in prefix of the patched, version-pinned Strata `expert_pool_dispatch_multi` into a private test translation unit. It deliberately excludes the ordinary donor fallback and the CUDA verifier. The test executable links the real `pool_cpu_only` adapter and the C++ socket client, then communicates with the actual Rust coordinator and two persistent native rank sessions using the R388 sparse synthetic pack.

With `VF_STRATA_CPP_DONOR_BRANCH` explicitly set, two separate CPU-only batches travel through that extracted donor branch and return exact unweighted provider FP32 rows. A routed resident-GPU owner is refused before the hook or any new batch reservation; its destination and the hook's next batch remain unchanged. A hook failure for a mismatched layer latches the donor dispatch error and leaves the destination unchanged. The original donor driver resets the layer before each window; the test does likewise. Existing C++ protocol and local durable-ledger tests also run. The donor source checkout remains unmodified; the candidate patch applies and all four patched units pass syntax-only checks using AArch64 parsing stubs for x86 intrinsics.

This is execution of the extracted CPU branch, not a linked or running Strata engine. It does not establish actual callback installation, whole-model/layer lifecycle, trusted real checkpoint identity, GPU verifier error propagation or drain behavior, mixed GPU/peer owners, inter-PC transport or full generation. The integration branch is optional in the test and is exercised only when `VF_STRATA_CPP_DONOR_BRANCH` is supplied. No hardware workload or consumed UNKNOWN was replayed. R390's candidate remains unqualified for live use; all hardware gates apply.
