# R422 — Resident SC117 post-attention and model-derived routing

Parent: R421 `3f12eca1277467453353b139a495ec5ca547acb4`. This adds a reusable resident CPU stage for the SC117-specific gate projection, GDN output normalization, attention projection, hyperconnection write/read and top-10 BF16 router. It retains the selected checkpoint matrices and FFN weights and verifies sizes, span SHA-256s, file identity changes during load and the requested layer/model identity. The Stage checks the caller-supplied run/model/layer/epoch identity at compute; the caller still must establish that its prefix and residual originate from the same reserved attempt. This is not yet wired to `Stage::commit_native` and does not itself enforce reservations, token ordering, or GDN state commit.

Provenance: the quantized matvec uses the existing VoltaFabric GGML CPU boundary and Strata's pinned local llama.cpp GGML decoder/provider previously recorded in R400–R421; routing, hyperconnection and normalization are the VoltaFabric CPU implementations. IQ4_XS and Q8_0 are GGML types for these tensors, not MXFP4/NVFP4. The two manifest files contain local checkpoint offsets/digests, not checkpoint weights.

On PC1, layer 1 output was byte-identical to the existing R415 observation (SHA256 `f252ac7c7cf54d959b195db3e704c0de62e17a74417342e81f505a4887492bcf`). For layer 2, actual R418 GDN prefix and residual were read by pinned hash; output SHA256 `1d422bb0c33f854b725b61a924a0f0f0d8d7def1df51a8f3723c9fadbe9e72ed`. Independent NumPy computations checked output normalization (max absolute error 5.96e-7), post-attention residual (1.87e-9), FFN activation (1.20e-7), FFN injection (0) and selected expert IDs [75, 12, 209, 181, 480, 257, 272, 492, 64, 302] and coefficients (1.41e-8). The quantized matvecs were separately sampled at 9 gate and 5 output rows with scalar accumulation and shared GGML quantization/decoding; maximum absolute errors 1.53e-7 and 1.49e-7. This is a sample, not independent validation of all quantization decoding.
