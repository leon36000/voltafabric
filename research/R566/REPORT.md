# R566 — provisional PLE and GDN batch, actual local experts

Extends the single-layer GDN segment batch with a provisional causal PLE history and token state. Each PLE position sees preceding candidate history and tokens; no PLE state is assigned until the reserved GDN layer has produced every shared and routed output and all residuals validate. Any error after reservation poisons the segment. The public PLE path and layer-1 constructor remain explicitly gated by `ple-cpu-qualification`; the ordinary constructor guard is unchanged. Strata's MIT PLE adaptation provenance is documented in `sc117_ple_post.rs`; no new third-party code is copied here.

One bounded PC1 CPU run consumed the two recorded layer-0 residuals from R453 for supplied token IDs 42 and 73, checked by their hashes, with actual observed layer-1 PLE, GDN, shared and IQ3 expert weights. Fifteen missing routed experts were admitted dynamically and two local guarded rank workers each executed once and closed normally. Both layer outputs match the historical R453 serial results bit for bit; R453 separately reported an independent NumPy PLE check for these inputs. This does not constitute a new independent full-layer or full-model oracle. A separate fresh fault run with a payload limit of three expert blobs failed after one admission; the segment was poisoned, produced no output, and its PLE history digest, previous tokens and GDN position stayed unchanged. Both fresh claims remain RESERVED_UNKNOWN_NO_REPLAY and are included.

The actual run used an isolated CPU scope capped at 3 GiB, zero swap and one CPU quota, without GPU or network workers. The PLE batch unit test first failed to compile because the new API was absent and then passed, covering causal history, invalid tokens and rollback. Native qualification-feature Clippy passed with a pre-existing trace-only dead_code allowance; the library suite passed 134 tests with five ignored in both debug and release; rustfmt passed. No performance result, GPU, inter-PC or complete generation is claimed.
