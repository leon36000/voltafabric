# R523 — bind PLE manifest bytes to the SC117 worker plan

The SC117 CPU generator previously used the PLE weight manifest after computing its worker plan, so a changed manifest did not change that plan. The v11/r523 plan includes SHA256 of the exact bounded manifest bytes. The program reads and parses the manifest once before plan-only output or worker launch, and reuses the parsed value for PLE loading; it refuses empty, oversized (>64 KiB), non-regular or malformed input. The plan digest is byte-sensitive, including whitespace. The prompt runner accepts the new plan prefix while preserving prior versions.

On PC1, actual no-worker plan preparation with the existing observed tokenizer and checkpoint configuration produced two independently reconstructed plan IDs when a single space was appended to the manifest. With the original expected plan and the modified manifest, the actual executable refused `expected worker plan missing or mismatched`; stdout and the fresh ledger were empty. No rank worker ran. Both exact manifests and plan receipts, a bounded preflight script and the independent JSON/SHA256 oracle are retained here.

Four Rust binary tests passed in debug and release, including changed and invalid manifest hashes; 34 Python adapter/tokenizer/chat tests passed on the observed tokenizer with no skips. Release executable SHA256 `6d7f398523c521fb9fd40757ccab38e7d635d59a4f36a9934fff64bb69ac79ef`. Preflight used 512 MiB, no swap, 16 tasks, one CPU and nice 10; builds used at most 3 GiB, no swap, 64 tasks and 150% CPU. PC6 swap remained below the inter-PC admission floor.

This binds manifest bytes to plan identity, not publisher authenticity, every model byte, worker executable or host, and is not an R53 reservation or a shared lease. PLE loader's existing per-span digests still apply; other model inputs need their own independently verified identities. No full v11 model generation, GPU, SSH worker or consumed UNKNOWN claim was run. Next: qualify a fresh complete local v11 generation with the prepared plan and existing reference, and pursue independently authenticated host/worker/checkpoint identities and the actual shared lease before any inter-PC attempt.
