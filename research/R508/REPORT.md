# R508 — select a feasible rank for expert headroom before eviction

Parent GitLab R507 5a57823883f5abf2f3c324b1188ce6ab2ec857ee. The previous policy always selected the rank with the largest payload cap before computing a rank-specific eviction plan. If that rank's remaining residents were protected, it could refuse even when another rank already had sufficient free capacity or could free it safely. It could also evict unnecessarily from the largest rank while another already satisfied the headroom.

VoltaFabric now validates the complete rank-capacity map, first uses any rank that already has the entire conservative headroom, and otherwise tries eligible ranks in deterministic descending-cap/ascending-rank order. Each alternative is planned entirely in memory; only the explicit `eviction target cannot be met safely` planning failure permits considering the next rank. Invalid accounting and other failures abort. No reservation, worker message, or eviction is sent until one complete plan has been selected. Once execution begins, the original atomic failure/poisoning and UNKNOWN-no-replay rules remain unchanged. The prior route's experts and the final resident of each layer/rank remain protected. This does not predict the next routing, measure RSS, establish a lease, or authorize distributed execution. It still conservatively requires one rank to be capable of holding the entire requested headroom; feasible split-capacity cases may be rejected.

The SC117 plan descriptor is now v7 and binds the `rank-first-feasible-v1` eviction policy in addition to the existing prompt digest and other settings. The Python runner continues to require a prompt digest for both v6 and v7 receipts. This is an adaptation of VoltaFabric's own existing placement and eviction contracts, not donor source; Strata/GGML provenance remains R460/R379.

Eleven focused layer-chain tests passed in debug and release, including a case where the larger rank cannot evict its last resident but another rank is already ready, a fallback after an infeasible first rank, impossible/no-candidate and invalid-accounting cases. Three SC117 binary tests passed debug and release, targeted Clippy passed, and 29 Python tests passed on PC1 using the existing Strata venv and observed tokenizer. Independent Python exhaustive examples check the two small feasibility scenarios; another Python oracle reproduces the v7 JSON/SHA256 plan vector. These prove the bounded planner cases, not an inter-PC run or a measured improvement. No real model generation, GPU, SSH worker, RDMA or UNKNOWN replay occurred in this batch.
