# R488 — longer bounded prompt prefill

Parent GitLab R487 commit 0bd21c2fd37c4d990f15775feec76f0026f33f51. The CPU prefill binary and tokenizer wrapper now accept 1–32 ordinary prompt tokens and 1–32 generated tokens, provided `prompt_length + max_new_tokens - 1 <= 39`. Both layers refuse invalid combinations before starting the engine or workers. The 39-position ceiling preserves the R486 receipt-size budget; 32 prompt tokens and 32 output tokens cannot be requested simultaneously. The plan identity already includes prompt length and maximum generation length.

Tests cover 32 prompt tokens plus eight outputs, reject 32 plus nine and 33 prompt tokens, retain the eight-plus-32 boundary, and reject incomplete receipts. The new focused test failed against the old eight-token limit before the change. Three Rust binary tests passed in debug and release, targeted Clippy passed, and Python ran 20 tests: 19 passed and one observed-tokenizer-pack test was skipped. `research/R486/verify_bounds.py` still applies because the maximum 39 positions, 768 evictions per later position and 48×10 admissions per position are unchanged. Its fixed-field allowance includes the additional prompt token IDs. The Python capture remains bounded as in R487; JSON parsing still allocates additional memory.

A fresh local PC1 CPU run used the 12-token prompt `Hello, please explain what this project does in simple terms.` and requested two generated tokens. It processed 13 positions through 48 layers, returned two tokens (`\n\n` followed by a code fence), and all 96 workers closed. This is a functional prefill and short generation test, not a meaningful complete answer or a full-model quality oracle. Global/rank expert payload caps remained 3 GiB and 1/2 GiB, respectively; the receipt records 2007 acknowledged evictions. The initial token's embedding and final layer output hashes match the first token of R486, which had the same first token; later positions are not independently numerically qualified by that comparison.

`verify.py` checks prompt token IDs, autoregression, plan ID on all 2631 claims, layer coverage, worker counts, rank accounting, route protections and expert digests. The 2644 distinct experts match local source observations, including 1213 newly checked against source shard slices; this establishes local consistency, not checkpoint publisher authentication. `verify_real_plan.py` reconstructs the actual plan digest independently. All claims remain RESERVED_UNKNOWN_NO_REPLAY and must not be reused. No worker remained after completion. The PC1 scope used MemoryHigh 11 GiB, MemoryMax 13 GiB, zero swap, TasksMax 320 and CPUQuota 300%.
