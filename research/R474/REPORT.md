# R474 — bounded eight-token CPU generation with budget-triggered eviction

Parent R473 `74ec831e1f929eaade369eb1b7dfa03ba38d5b14`. The existing SC117 CPU generation controller now accepts up to eight ordinary prompt tokens and eight requested output tokens, with at most 15 QSA positions; the default remains two output tokens. The runner and receipt decoder retain bounded, atomic decoding and validate the requested output limit and autoregressive sequence. This remains a qualification path, not unrestricted generation.

The controller uses R468's headroom-aware advance before every position. A single `ROUTED_EXPERTS` constant supplies the existing top-10 gate in both GDN and QSA paths and the worst-case admission calculation. `NativeLayout::worst_case_admission_bytes` sums ten expert payloads per layer from the validated mixed-format index: 982,272,000 bytes for this pack. This bounds new expert-payload admissions for one token if all ten selections in every layer are absent; it does not cover other allocations, RSS or transport. The source budget defaults to 4 GiB and can be explicitly lowered with `VF_CPU_EXPERT_BUDGET`, subject to admission for seeds plus this worst-case headroom. The existing conservative eviction planner's per-call bound is raised to 768; an infeasible complete plan still fails before any eviction and a later uncertain acknowledgement still poisons the segment. The policy protects the last committed route, not unknown future routes, and is not a latency or throughput optimization claim.

A fresh PC1 CPU run used a 3 GiB expert-payload budget and the prompt `Hello!` (`[9419, 0]`). It advanced nine input positions and produced eight tokens `[1165, 3849, 13293, 421, 488, 8719, 1357, 1801]`, decoded to ` We’ve noticed that you haven’t made`; the stop reason was the requested token limit, not EOS. All 96 local workers closed normally. The first five input, embedding and layer-output hashes and first four logits hashes match R470, including the position after the first automatic trim. Later outputs have no independent full-model oracle.

Budget-triggered trims produced 746 individually acknowledged evictions across five position boundaries, releasing a cumulative 1,443,942,400 payload bytes; 219 expert admissions were re-admissions and carried the same previously observed digest. This cumulative figure is not net RSS savings. Final accounted resident payload was 2,583,859,200 bytes, below the 3,221,225,472-byte expert budget. The complete original receipt SHA256 is `a3922d98050714abec29e1328135a1112bc79c25320d6779b64b871beaa2d749`; its eviction and admission arrays are stored separately in numbered parts for bounded readback. `verify.py` reconstructs the receipt and payload accounting from the index, verifies all eviction receipts and the complete 48-by-9 batch coverage, checks the R470 prefix and matches all 1,757 distinct admitted expert digests against local source observations. The observer reused 1,349 previously checked experts and checked 408 newly encountered blobs against local GGUF slices. This is local consistency, not checkpoint publisher authentication.

The fresh local ledger retained 432 batch and 746 eviction claims, all `RESERVED_UNKNOWN_NO_REPLAY`, split across the twelve `claims/part-*.json` files; no UNKNOWN was replayed. The CPU-only execution scope used MemoryHigh 11 GiB, MemoryMax 13 GiB, zero swap, TasksMax 320 and CPUQuota 300%. The observer used 2 GiB, zero swap, 16 tasks and CPUQuota 100%. No GPU, inter-machine expert transport, R53 lease or shared hardware operation was used. No rank-session remained afterwards. Execution source, adapter and observer hashes match between PC1 and PC6.

Three index-layout tests and eight Segment tests passed in debug on PC6; the eight Segment tests also passed in release. Eleven Python adapter/runner tests passed on PC1, including synthetic eight-token prefill, eight-output receipt and old default; CLI output bounds 0 and 9 were refused before opening model inputs. Targeted PC6 library Clippy, PC1 release binary Clippy, rustfmt and the receipt/accounting verifier passed. The only real run here has two prompt tokens; the eight-prompt-token bound is covered by a synthetic receipt test, not a real eight-token prefill.

This result does not establish unrestricted generation, a robust application serving interface, independent full-model numerical parity, checkpoint authentication, performance, GPU execution or distributed transport. The R428/R473 numerical discrepancies remain open. The new worst-case payload margin and high eviction count must be evaluated against actual per-machine memory and latency; no speed or total-memory benefit is asserted.
