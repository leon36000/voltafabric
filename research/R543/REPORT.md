# R543 — independent activation packing on the real 92-position QSA trace

The standalone CPU probe reads the actual committed layer-3 trace from R537 and invokes the same GGML CPU activation traits selected by the projection weights: Q8_K for the 2,560-value mixed input used by Q, K and V, and Q8_0 for the 6,144-value gated attention input used by the output projection. It confirms those trait choices and bounded row sizes before capturing 869,216 quantized bytes. This is a read-only diagnostic, not a new worker execution or a replay of R537's consumed claims.

A separate Python implementation reconstructs the Q8_K and Q8_0 blocks from the actual f32 inputs without calling GGML's quantizers or decoders. All bytes matched for 920 Q8_K blocks and 17,664 Q8_0 blocks across all 92 positions. The Q8_K packing adapts the independent reference in R473; Q8_0 follows the observed x86 nearest-even GGML rule and the same documented format. Each of two negative controls changed one captured byte in memory at position 91, one per format; the respective reference rejected it and produced no success output. These tests do not establish equivalence for other architectures or all possible tie/overflow inputs.

Together with R541's full-row scalar checks, R542's separate weight-decoder comparison and R537's independently computed QSA normalization/RoPE/attention, this strengthens verification of the layer-3 QSA boundary for this one real generation. The inputs to that boundary remain observed rather than independently derived, the decoders share GGML format lineage, and the rest of the model and R428's expert-255 strict failure remain unproven. Q8_K and Q8_0 are activation formats here, distinct from QPN2/NVFP4, MXFP4 and IQ model formats. No GPU, inter-PC worker, new generation, shared lease or R53 reservation was used.

The probe was compiled against the existing isolated GGML CPU libraries and Strata's vendored headers using `g++ -std=c++17 -O2 -Wall -Wextra -Werror`; both checks used local CPU scopes with MemoryMax=512 MiB and SwapMax=0. The Python reference and negative controls ran with CPUQuota=100%; quantized capture used 50%. The source trace SHA256 was checked before and after. The trace and quantized capture remain under PC1 and are not in GitLab; after formatting, they need a fresh admitted capture. `verify_summary.py` checks retained hashes and reported counts, while `verify_quant.py TRACE QUANT` reruns the byte comparison when the raw data exist.
