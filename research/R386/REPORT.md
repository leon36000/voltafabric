# R386 — direct pinned Strata generic CPU parity

The optional `vf_strata_generic_parity` CMake test compiles the actual unmodified `src/kernels/cpu/native_expert.cpp` and headers from Strata `fb58e0dbc8399662c0e47c76578c6e878b14f6cf` (MIT), alongside the existing provider built on pinned llama.cpp GGML `3cf03257f219afbe7334045ff7c6a06ac68c627d` (MIT). CMake checks both revisions and relevant source cleanliness. On AArch64 only, test-only stubs report no x86 ISA and abort if an AVX implementation is unexpectedly invoked; they do not replace any arithmetic on the selected generic path.

For every one of the seven gate/up–down format pairs in the SC117 metadata, two different FP32 inputs and synthetic packed blocks with varying row, role and block scales execute Strata's actual `native_fmt`, `native_quant_act`, `native_gu_rows`, `native_quant_h` and `native_down_rows`, and VoltaFabric's provider. All 2 x 2560 finite output floats per pair agree bit for bit; tests verify the outputs are nonzero and vary by row. The separate existing provider oracle also passes. CTest: 2/2 pass in both Debug and Release on PC6 AArch64 with CPU-only builds.

Both paths share the same GGML quantizers and dot functions; this is a direct implementation comparison, not an independent model oracle. Synthetic weights do not prove correctness for a real checkpoint. Strata's AVX2/AVX512 multi-token kernels and x86 Q2_0 path may use different rounding and are not tested here. R385 transports unweighted outputs through FP16, so its callback compatibility is not established by this FP32 provider comparison. No GPU, network, actual model generation or speed comparison was performed.
