# R144 — reproduction de la contradiction de dépendances

Une vérification CPU hors ligne des octets exacts de métadonnées du wheel 1Cat-vLLM 1.2.2 et du bootstrap du donneur épinglé confirme que ce wheel déclare `tilelang==0.1.9` et `apache-tvm-ffi==0.1.9`, tandis que le bootstrap demande explicitement 0.1.10 pour les deux. Le test `packaging` accepte 0.1.9 et rejette 0.1.10 pour chaque contrainte. Commande : `python3 -B check.py` ; sortie 0, résultat joint. Les chemins absolus du script identifient les preuves locales et ne constituent pas un test portable autonome.

Ceci confirme indépendamment un conflit déjà signalé en R121 et ne démontre pas une incompatibilité effective à l'exécution. Le donneur indique dans ses commentaires qu'il écrase volontairement ces dépendances, en attribuant à TileLang 0.1.10 une correction SM70 : cette affirmation reste une source, pas notre qualification GPU. Un solveur respectant simultanément ces quatre égalités n'a aucune solution ; changer les autres dépendances ne résoudra pas ces égalités. Le graphe R143 en versions 0.1.9 ne répond pas à la recette du donneur. R140 a importé séparément TVM FFI 0.1.10 sur CPU, sans 1Cat ni TileLang.

Prochaine piste : établir, avec les sources et métadonnées des versions exactes, si le chemin Skinny réellement visé invoque TileLang ; préparer ensuite un environnement expérimental isolé explicitement non conforme aux métadonnées ou identifier un couple publié compatible, puis tester les imports et ABI CPU avant toute admission GPU. Aucun paquet installé ici, aucun runtime ou modèle qualifié, aucun GPU utilisé.
