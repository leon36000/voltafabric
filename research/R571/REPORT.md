# R571 — end-to-end grouped prefill on a tokenized chat prompt

A fresh PC1 local CPU run used the R570 grouped prefill coordinator with the existing checkpoint-bound Strata tokenizer adapter. The supplied message was `Hi`. The adapter produced a 13-token chat prompt, exercising six two-position groups and one odd final prompt position. With a two-token output limit, the 48-layer SC117 engine generated token IDs 9419 and 0 and the adapter decoded `Hello!`; it stopped at the requested token limit, not EOS. All 96 guarded local workers closed normally. This is a concrete end-to-end example, not a general quality claim.

The 13 prompt tokens and the first generated token matched the first 14 input positions in the previously retained R552 sequential run, and all 14 full-layer residual hashes matched bit for bit. That historical run used the same engine implementation; the comparison is not an independent full-model oracle. The run admitted 2,554 observed experts dynamically and acknowledged 1,147 local evictions. Both values count admissions/operations, not distinct experts or performance. The 384 execution claims plus 1,147 eviction claims are retained in CLAIMS.json with original names, content and SHA-256, each RESERVED_UNKNOWN_NO_REPLAY. The local ledger is not R53 or a distributed lease.

The plan was produced through the tokenizer/CLI and independently reconstructed by `verify_plan.py`. The verified engine bytes were executed through the existing sealed-memfd CLI. The resource scope was MemoryHigh 11 GiB, MemoryMax 13 GiB, zero swap, 200% CPU quota and 320 tasks, with low CPU and I/O priority. The input source and all claims were fresh; the 96 workers were local CPU processes. No GPU, remote worker or performance comparison ran. The full result is retained as RESULT.json; its SHA-256 is 64b3a7ef8240ecfda6195c92aee6443705015870e2c7f1d6bfad17bc6cfd1d22.

Production code is unchanged from R570; its coordinator tests, adapter tests and Clippy passed there. This run qualifies one short odd-length prompt only. Independent whole-model numerical validation, broader prompts and actual multi-machine GPU distribution remain open; all prior and current UNKNOWN claims must never be replayed.
