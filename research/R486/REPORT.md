# R486 — longer bounded SC117 CPU generation

Parent GitLab R485 commit 5fdf5582d12c069f45bfee8647cb8ef2c342e5fc. The CPU prefill binary and tokenizer adapter previously accepted at most eight generated tokens. They now accept 1–32, with up to eight prompt tokens and at most 39 input positions. Both Rust and Python validate bounds; incomplete receipts, token order, invalid hashes and non-EOS early termination remain rejected atomically. The plan descriptor is version 2 and binds prompt length and requested generation limit in addition to rank endpoints and budgets. This is not an external lease or machine authentication.

The Python receipt size limit is 32 MiB, increased from 4 MiB. `verify_bounds.py` gives a conservative calculation for this fixed schema: up to 38 eviction phases of 768 events, up to 39×48×10 admissions, and a 1 MiB allowance for remaining fields, below 32 MiB. The assumptions apply to the current fixed SC117 format and must be revisited if schema, rank count, identity lengths or limits change. subprocess.run still buffers output before checking its size; this is not a streaming memory limit.
