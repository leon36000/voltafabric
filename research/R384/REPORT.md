# R384 — durable local CPU admission for native GGML batches

The R383 native coordinator now requires a `NativeBatchLedger` directory. Before any worker request, it exclusively creates a claim keyed by the SHA-256 of the complete stamp in a versioned, length-prefixed binary encoding and syncs the directory, then writes the stamp, assigned attempt and `RESERVED_UNKNOWN_NO_REPLAY` state and syncs both file and directory. A collision, write/sync error, changed directory identity or other failure returns without sending work. Claims are never removed or reused, even if incomplete or the batch later succeeds. The process-local guard remains additional protection.

This is adapted from the exclusive, fsynced local claim pattern of the earlier `research/R190/durable8.py`; it is not the shared R53 hardware ledger, not a distributed lock/lease, and not an exactly-once proof. It assumes all coordinators use the same stable pre-existing directory on a filesystem providing the documented exclusive-create and fsync semantics. Changing, restoring, deleting or splitting that directory can defeat the protection. Claims do not persist outputs or certify completion; reconciliation remains external. R53 namespace, hardware admission, GPU leases and UNKNOWN rules are unchanged.

CPU tests use synthetic data and local child processes only. Two simultaneously started test processes race for one stamp: exactly one reserves it; a third fresh process cannot reserve it after the first exits. A real two-session native batch also verifies an already-consumed durable identity sends zero bytes to either worker; the existing tests cover successful collection and failure after one rank completes. No actual checkpoint, GPU, inter-PC execution or production shared ledger is exercised.

Next: bind trusted actual checkpoint identity and real per-expert digests, then validate native expert and gate/layer results against an independent model oracle before any claim of real generation. Hardware and cross-machine steps still require all current resource and admission gates.
