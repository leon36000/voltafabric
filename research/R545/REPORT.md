# R545 — pin native local reservation creation to its directory

The local native batch/eviction ledger checked that its path still named the originally opened directory, then used the pathname again to create a claim. A temporary substitution between that check and creation could put the claim in the wrong directory. A deterministic test of the creation seam reproduced the defect before the fix: the claim escaped the pinned directory. No live ledger was modified to reproduce it.

Both batch and eviction claims now use exclusive, no-follow `openat` relative to the existing pinned directory descriptor on Linux, preserving the filename format, creation mode, directory fsync and fail-closed UNKNOWN behavior. Other platforms refuse claim creation rather than falling back to the race-prone pathname. The test replaces the path after the initial check, creates the claim, restores the path, confirms the identity check succeeds and verifies the claim is in the pinned directory, not the replacement. This prevents this particular check-to-create path substitution, but cannot establish a globally stable shared namespace if other processes independently open a substituted directory.

The targeted test passed in debug and release. The existing five native-ledger integration tests passed in debug, including concurrent cross-process exclusion, restart persistence, incomplete claim refusal, ticket binding and eviction reuse refusal. The release integration-suite attempt was interrupted because Cargo began rebuilding the full unrelated binary set; it is not a pass. Targeted release Clippy and rustfmt passed. An independent Python oracle reconstructs the names of one batch and two eviction records generated by these synthetic tests; all match, including the eviction operation identifiers. Tests use fresh local CPU-only synthetic directories and do not replay historical UNKNOWNs.

This is the local CPU ledger, not the missing shared R53 hardware namespace, a shared lease, host authentication or a distributed/GPU admission. PC6 free swap remains below the inter-PC floor. The R428 expert-255 numerical strict failure remains open.
