# R443 — real SC117 PLE weights, CPU reference

Parent R442 `6ed084c04f2f545519a099f46c5448cea72bdf92`. `sc117_ple_weights` loads the six layer-1 PLE tensors from a regular source file, checks fixed dimensions, bounded spans, caller-supplied SHA256 and source identity metadata, and retains weights in memory. It performs BF16-weight/FP32-input projection with f64 accumulation, then calls R442's pure post-projection routine; the returned history is only a candidate. The caller must authenticate the manifest and bind identities and the transactional history to the actual session. This CPU numeric reference is not a claim of Strata CUDA's exact activation/accumulation policy.

The local PC1 shard observation, `OBSERVED_MANIFEST.json` SHA256 `436066427aaca7f163943b3f0f00c98cb59ddb5df7b2fa410b90d474ab1fe824`, records two BF16 projections, three FP32 normalizations and one FP16 convolution. These hashes identify local spans and do not authenticate the model publisher. Two actual gathered token embeddings from R441, each paired with a synthetic residual and nine-position synthetic history, were run on PC1 CPU. A separate NumPy oracle read and hashed the same spans and computed both projections and post-ops; for all 10,240 residuals, 10,240 normalized values and 92,160 candidate-history values per input, the largest absolute differences were respectively <=5.97e-8, <=9.54e-7 and <=9.54e-7 (atol/rtol 2e-5). Result JSON SHA256s: `6d4d481929685ec6859483777fa6e0740d22a06be0950059c66114416d835ba6`, `db46bc2662c39faebd10e7a358a890ce3b8af2b3ad7663decea8b81ae44bd040`. An altered key digest was rejected with empty output. The oracle shares the same documented equations and checkpoint format, but not the Rust implementation. These two trials are independent synthetic-history checks, not consecutive transactional tokens.

Targeted projection and PLE post-op tests passed debug and release; strict Clippy and rustfmt passed. An initial PC1 execution of an ARM build was rejected by the OS (exec format); an offline x86 build using the existing PC1 toolchain and existing cached dependencies succeeded. No GPU, worker, durable reservation or inter-PC operation was submitted, and no UNKNOWN was replayed.

Still required: independently verify activation precision for the intended model contract, integrate the candidate PLE history atomically with the complete layer/session, remove the layer-1 guard only after that integration is verified, then validate real multi-layer generation and distributed experts. The current source is not a complete generation engine.
