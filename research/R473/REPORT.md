# R473 — independent IQ2_S gate/up and complete-expert diagnostic

Parent R472 `6741b6bf4e0a4763f105450e5c30d99bf866e59f`. This examines the same locally observed layer-2 expert 255, with fresh synthetic inputs and without running or replaying the R428 worker or its consumed claim. The probe checks the real IQ2_S gate/up and IQ4_NL down geometry, invokes the existing native CPU provider, and saves its quantized inputs, gate/up outputs and a separately staged intermediate/down output. The Python oracle independently unpacks IQ2_S block scales, signs, high bits and 8-element patterns, independently packs/decodes Q8_K, accumulates scalar gate/up products in float64, computes float32 SiLU with libm `expf`, independently packs the Q8_0 middle using the observed nearest-even contract, and independently decodes/accumulates IQ4_NL down products. It does not call the GGML decoders or dot kernels. It reuses GGML's 1,024-entry IQ2_S codebook as required by the format, extracted from the source recorded in R471; its MIT license is included. Therefore the table itself is not an independent discovery or independently authenticated model metadata.

The observed blob SHA256 `8a17e1a2a5f9a21e11d2bae64fc99a656c810e8ed16d15bed9a09800fccd9cb5` matches R428's local pack/GGUF observation, not a publisher-authenticated checkpoint. Two new inputs were used: a small smooth 2,560-value signal and an extreme synthetic half-step vector with maximum magnitude 127. For both, all 640 gate and 640 up rows satisfy the predeclared `1e-6 + 2e-5 * abs(reference)` tolerance. Maximum absolute errors for smooth gate/up are `4.97e-9` / `6.04e-9`; for the extreme input they are `9.34e-6` / `9.10e-6`. The independently packed Q8_K input matched the actual CPU quantizer bytes for both.

The complete-expert comparison has mixed results and is not a full pass. The smooth input passed all 2,560 rows with maximum absolute error `1.45e-11`. The extreme boundary input failed the unchanged tolerance on four of 2,560 rows, with maximum absolute error `7.79e-5`; the four failures and their values are retained in `RESULT.json`. For both inputs the independently predicted and separately probed middle Q8_0 bytes were identical, and the separately staged optimized down output matched the provider bitwise. Thus the four failures persist with the same middle quantized bytes. Their outputs exhibit substantial cancellation: for the four failing rows the sum of absolute block contributions is approximately 438 to 851, whereas reference outputs have magnitude 0.05 to 0.50. Differences are below a deliberately conservative empirical `gamma_64 * sum(abs(block terms))` envelope for 64 float32 rounding steps, but the actual optimized kernel's complete operation count was not proved; this is diagnostic evidence consistent with accumulation rounding, not a replacement tolerance or a correctness proof.

The original R428 result used a different, model-derived input, a stricter `1e-7 + 1e-3 * abs(reference)` tolerance and had 1,169 violations after one intermediate quantized byte changed. It was not rerun or reclassified. Neither this synthetic pass nor the cancellation diagnostic proves the complete model, checkpoint authenticity, GPU correctness or distributed execution. Next characterize the actual target kernel's accumulation contract and build an independent full-model oracle before using any tolerance to qualify generated results.
