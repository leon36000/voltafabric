# R552 — stable owner-grouped CPU execution with original collector order

The native rank worker now groups execution indices by physical resident owner, with original slot index as a deterministic tie-breaker. Inputs are still prepared once per token and gate/up format within that batch, as in R551. Each expert invocation remains a separate CPU calculation; this is not a grouped matrix kernel. Results are written into their original slot positions before the worker returns anything. A calculation failure returns no partial output and makes the worker terminal. Routing choices, coefficients, resident bindings, unweighted output format and the ordinary Rust Collector's FP16 decoding and ordered f64 weighted accumulation remain unchanged.

The conceptual grouping idea follows the contiguous per-expert layout described in [DeepGEMM commit 1fc9c66975ee322d628b3288534ca0e9ce12a64d](https://github.com/deepseek-ai/DeepGEMM/blob/1fc9c66975ee322d628b3288534ca0e9ce12a64d/README.md), whose [root license is MIT](https://github.com/deepseek-ai/DeepGEMM/blob/1fc9c66975ee322d628b3288534ca0e9ce12a64d/LICENSE). No donor code, layout, padding or GPU kernel is copied. That pinned DeepGEMM declares SM90/SM100 requirements, not V100 support. The pinned [DeepEP reference](https://github.com/deepseek-ai/DeepEP/blob/f6aa38fe06cd4a0489e7730365d4e0114970a2f3/deep_ep/utils/refs.py) actually describes non-expanded dispatch sorted by rank then token; it is not evidence that its reference sorts by expert. Its combine is not substituted for the Rust Collector. No speed or memory-traffic benefit has been measured.

A new deterministic permutation helper was absent in the initial test build and then passed tests for empty, repeated and interleaved owners plus an independent bucket oracle covering all 3,280 sequences of length 0 through 7 over three owners. Nine native-provider integration tests passed debug and release, including two interleaved tokens and two experts, original slot restoration, the real Collector with distinct 0.25/0.75 coefficients and FP16/f64 arithmetic, and a synthetic failure after another owner had computed: no partial result and no retry. Release Clippy and rustfmt passed. The tests use local CPU and fresh synthetic identities.

A new PC1 local CPU generation used a new worker and plan, sealed coordinator, new run/attempt and fresh local ledger. It produced the same EOS-terminated 20-token reply after 73 prompt tokens. All 92 input, embedding and layer-output hashes and all generated-token/logit hashes match R534; the layer-3 trace is byte-identical to R544. All 96 workers closed, stderr was empty and 20,709 unique local claims including 16,293 evictions were verified. The 6,198 distinct selected experts matched prior local source observations; 6,589 compact raw worker executions occurred. This real generation has one token per dispatch, so multi-token grouping is validated only by synthetic local tests. A separately observed worker matched the pinned executable hash, not remote attestation.
