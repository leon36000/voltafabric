# R482 — sparse rank dispatch regression with two real CPU workers

Parent GitLab R481 commit c2ee1c0360df7c06c8a582eb6f506a65cc05d837. The two-child GGML integration test now exercises a fresh third batch whose gate routes only to rank 2. After two earlier batches sent to both workers, coordinator traffic counters must be [3, 2], and the returned decoded result must equal the independently computed reference. A unique R482 run identity and fresh ledger directory are generated for each invocation.

The exact test `native_ggml_sessions_execute_two_actual_child_processes` passed on PC6 in debug and release with a fresh identity each time. It uses synthetic packed weights and real local child worker processes; the rest of this existing test also checks rejected reservations, FP32 and FP16 paths, and a terminal overflow. To avoid building every binary in the large workspace, the test ran with a temporary isolated Cargo manifest under Naos referencing the same source, lockfile, fixtures, dependencies and native GGML build, with only the two required binary targets enabled. This manifest is a test harness, not a change to the project manifest. It does not provide an independent full-model oracle.

Both runs retained 18 claims across two ledgers and their intentionally distinct alternate-ledger fixtures, all RESERVED_UNKNOWN_NO_REPLAY. CLAIMS.json and verify.py preserve and check them; never replay them. Test file SHA256 db83f9dc018e25988058e268e1767b39c9e88691194a9da663d87dfaccd7df7f; claims SHA256 a0f8db8e7f6c0c97daabe7c024a5427e8cc8e698eefb5f3ffeb665f01c2fd1c1.

The test qualifies local CPU request counting for uneven routing, not network transport, GPU or physical placement. Fresh PC6 swap was approximately 5.8 MiB free, under the 1 GiB admission for the inter-PC experiment; no cross-host worker or GPU operation was attempted.
