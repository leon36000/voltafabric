# R586 — Bound native owner request writes

Native SC117 owner operations used response deadlines but their socket writes could block indefinitely when a local worker or SSH transport stopped consuming input, especially while sending an expert payload. Native load, extend, seal, eviction, and execution now use a shared absolute deadline for request writes and replies on the existing Unix socket. Writes handle partial progress, interrupted system calls and timeout; the previous socket timeout is restored. Any write error makes the session unusable, including a partial write whose remote outcome is unknown. The coordinator must still treat that identity as consumed and never replay it. The stream is a POSIX Unix socket pair, not an rsocket; no polling of an rsocket is introduced. Non-Unix native deadline writes refuse rather than falling back to an unbounded pipe.

Four new local tests use `/bin/sleep` as an inert non-reading peer, not a model worker: a 4 MiB write times out and poisons the session, an actual synthetic native load is bounded and poisons it, an already-expired deadline refuses, and a successful multipart write preserves the prior socket timeout and counts one completed frame. The initial test failed to compile because the new method was absent. The tests do not qualify a remote transport or a successful real-model execution of these changes. Hello, ordinary Session operations and subprocess cleanup are outside this change; this is not a general hard end-to-end deadline.

Native-feature library suites: 142 passed, 6 ignored, in both debug and release. Targeted Clippy passed with the existing trace-only dead_code allowance; rustfmt passed. No remote worker, GPU, hardware reservation or UNKNOWN replay was performed. Previous R585 numerical, shared-lease and R53 limitations remain open.
