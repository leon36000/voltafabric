# R394 — layer-indexed local CPU pool

The optional Strata callback now has a `PoolFleet` with an immutable array mapping 48 layer numbers to separately initialized `PoolContext` instances. It dispatches through the existing verified layer-bound VFB2 client, serializes calls and latches the entire fleet after a missing or misbound layer or any child failure. It does not own or authenticate contexts, configure Strata, initialize sessions or manage their lifetimes; the embedding caller must bind all sessions to the intended run, model, plan and epoch and provide unique batch identities.

The opt-in integration test starts two genuine local Rust coordinators with four persistent CPU rank-session children against a sparse synthetic pack using the SC117 v3 index, with different weights at layers 0 and 7. A compiled C++ fleet alternates 0/7/0/7, compares every FP32 output bit against the corresponding direct provider/zero reference, and checks separate batch counters. A swapped mapping and a missing layer are refused with unchanged output; after failure the fleet refuses further work. Both debug and optimized C++ fleet executions passed. Unit CTest, Rust formatting and clippy pass. No real checkpoint, GPU, production networking or inter-PC execution was used.

Next: make model initialization build and own validated per-layer sessions without assuming unverified checkpoint coverage or authentication, and connect an actual full-model execution path with an independent oracle. Full generation remains unqualified. The local ledger is not a distributed hardware lease and UNKNOWN must not be replayed.
