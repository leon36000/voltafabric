# R579 — layer-wide admission preflight for sticky ranks

The SC117 layer path previously admitted missing experts one at a time. With sticky rank affinity and per-rank caps, a later missing expert could fail capacity after an earlier worker had already accepted another expert. This change collects missing experts in first-use order, de-duplicates the union across positions of the same layer batch, and asks the source to preflight the entire list before the first append. The SC117 source clones routing/order/accounting in memory, simulates its same deterministic placement, sticky mapping, global and rank budgets, and rejects the whole layer admission if any planned item cannot fit. Its actual state is not mutated by preflight. Other source implementations have a documented default no-op and do not acquire this guarantee automatically.

The GDN and QSA batch paths now submit the full per-layer union to `Owners::ensure` once; routes, coefficients, slot order and Collector arithmetic remain unchanged. The prefill coordinator binds this behavior into an additional plan domain (`r579-` before trace/batch/affinity transformations); the tokenizer accepts that domain. This check occurs after the layer ticket is reserved because routes come from the layer's attention/gate. A refusal therefore still consumes the ticket and poisons the segment as before; no old operation may be replayed. It does not preflight later layers, verify bytes before loading, cover changing resources or prevent later I/O/worker failures. It is not a general atomic rollback of worker state.

A fresh guarded two-worker local CPU test uses nonzero synthetic expert weights. After a recorded first batch and acknowledged eviction, the test alters an in-memory cap so a later sticky admission cannot fit: preflight rejects the two-expert list with unchanged source accounting and unchanged bytes sent to both workers. After making the test cap sufficient, preflight succeeds, the expert returns to the same rank despite another rank being suggested, the second collected row matches, and both workers close. The test's inherited stdout says `r577 pass`; its actual run/plan/claims are distinct R579 identities in PLAN.json and CLAIMS.json. Three exact local claim bytes (two batch, one eviction) are preserved as RESERVED_UNKNOWN_NO_REPLAY and independently verified; no GPU, inter-PC worker or R53 claim ran.

137 library tests passed in debug and release (six ignored), 13 coordinator tests passed in debug and release, and 34 tokenizer tests passed with PC1's existing environment. Targeted library/coordinator Clippy passed with the existing dead_code allowance; rustfmt passed. An independent Python SHA-256 reconstruction matches the plan-domain test vector. The R579 worker test ran in debug under 1 GiB memory, zero swap and one CPU quota; release was compiled but that non-replayable run was not repeated. The check is not yet qualified with the full real checkpoint/generation. R428 strict expert numerical discrepancy, authoritative shared R53 and cooperative lease remain open.
