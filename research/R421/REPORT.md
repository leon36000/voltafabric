# R421 — local durable reservation to real CPU owners and GDN commit

`NativeBatchLedger::reserve_ticket` creates the same fsynced `RESERVED_UNKNOWN_NO_REPLAY` claim as the existing local CPU ledger and returns a non-cloneable, process-local reservation carrying the complete stamp, attempt and ledger directory identity. Dropping or failing a ticket does not remove the claim. `Stage::prepare_reserved` binds a GDN proposal to that reservation. `Session::exec_native_ggml_reserved` consumes the ticket, checks its ledger and stamp before dispatch, collects actual rank packets through the existing FP16/f64 Collector, and returns a non-cloneable opaque `NativeCollected` only on complete success. `Stage::commit_native` requires the same stage, stamp, attempt, token and ledger identity before combining the collected row with the supplied shared output and residual. Identically named stamps from a different ledger cannot be used to commit the reserved proposal.

This is an optional local CPU path: the earlier unreserved experimental methods remain available and callers must choose the reserved path. The local NativeBatchLedger is not the shared R53 hardware ledger, a GPU lease or a distributed lock. The session caller must use one stable ledger consistently, establish source and producer provenance, and connect actual FFN activation, shared expert and attention residual to the same prefix. The GDN state and residual are still only in memory; there is no crash-safe checkpoint or automatic recovery, and any claim marked UNKNOWN must never be replayed. Stamps alone do not authenticate producers or prove numerical correctness.
