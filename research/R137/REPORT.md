# R137 — étapes FP16 de déquantisation QPN2 sur CPU

Le code CUDA du donneur épinglé a été lu et haché (`skinny_kernels.cu`, SHA `9c47c43ee5c1c69f688bf897062efea6c459f9ad9803869e2a9e9eb0f33fa136`). Les étapes pertinentes du chemin QPN2 sont : conversion E4M3 par bitcast puis multiplication FP16 par 256, conversion du facteur global multiplié par 16384 en FP16, multiplication FP16 des échelles, conversion E2M1 par bitcast et multiplication FP16 finale. Le programme CUDA lui-même n'a pas été compilé ni exécuté.

Deux émulations CPU distinctes ont été comparées : conversions et arrondis `struct` Python binary16, et opérations `torch.float16` CPU. Le plan préétabli couvre les 65 codes d'échelle distincts de l'échantillon R132, les 16 codes E2M1 et chacun des trois facteurs globaux réels, soit **3 120 combinaisons**. Leurs bits FP16 concordent exactement, y compris 216 zéros négatifs ; 2 688 résultats sont non nuls. Les combinaisons couvrent le produit cartésien des échelles observées et des trois facteurs, pas uniquement les paires réellement voisines dans le fichier. Gate et up ont le même facteur dans cet échantillon.

C'est un oracle CPU des seules étapes de déquantisation, dérivé du code source ; aucun kernel, GPU, ordre d'accumulation, activation, Collector ou modèle complet n'est qualifié. Une comparaison matérielle exige une nouvelle admission et des identités propres. Le SHA LFS du shard complet reste non vérifié. Les preuves R135 et R136 concernent séparément la permutation et le décodage idéal ; elles ne se transforment pas par addition en preuve GPU.
