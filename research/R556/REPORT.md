# R556 — provisional multi-position QSA stage

The SC117 QSA stage now projects several positions against a private causal cache and exposes tentative attention outputs. Its transaction replaces the active cache only after all planned positions succeed and the caller commits. A failed or incomplete transaction leaves the active cache unchanged. Existing single-position preparation shares the same projection code. The enclosing layer must still validate every routed expert and shared output before committing; no full-layer or full-prefill transaction is implemented here.

On PC1 CPU, the qualification binary loaded the observed SC117 layer-3 weights and compared both positions of a provisional batch with the SHA-pinned R552 real-generation QSA trace: all 74,760 f32 values matched bit for bit. Wrong-identity and incomplete batches left the active cache empty. This is comparison with a previous execution of the same implementation, not an independent model oracle. The nine qsa_cpu tests passed in debug and release on PC6. On PC1 the native-feature library passed clippy with warnings denied and `dead_code` allowed for a pre-existing trace-only struct. Rustfmt passed on modified Rust sources.

The transaction clones the existing K/V cache as in R555 and retains each detailed QSA output until commit; both costs are bounded but not performance-qualified. No GPU, network worker, expert batch, complete model, or generation claim follows from this test. Next bind this provisional stage to layer-level expert collection and atomic output, and separately address GDN and PLE state transactions.
