# R484 — bind worker configuration into native plan identity

Parent: R483 GitLab commit bbfb1dff08c70b008e008b5e1a29b4b93c398805. The SC117 prefill program formerly used one fixed plan ID even when rank endpoints or payload limits differed. It now hashes a versioned deterministic JSON descriptor containing the model revision label, native index digest, epoch, layer count, global payload budget, optional rank caps, and the full constructed endpoint argv for both ranks. It refuses missing or inconsistent rank entries and invalid limits. The resulting `r484-<sha256>` ID is supplied to both the Segment and the expert source; the local durable ledger's existing batch and eviction claims include that plan ID. The successful result also carries the plan ID. Endpoint command arguments are hashed, not printed by this change; no credentials are accepted as part of the supported SSH host/path settings.

This digest identifies supplied configuration only. It does not authenticate the actual remote host, its SSH host key, worker binary contents, checkpoint publisher, fleet lease, physical memory, runtime topology, or model correctness; the digest is not an external plan reservation and is not the R53 ledger. SSH admission remains external and must satisfy the current gates before any worker is launched. No GPU, worker or inter-PC execution was performed for this change. PC6 swap remained far below the 1 GiB inter-PC threshold.

Three binary tests passed in debug and release and targeted Clippy passed. They cover the two endpoint forms, malicious inputs, shutdown counts, deterministic serialization, changed host/path/budget/caps, and malformed rank sets. `verify_plan.py` independently constructs the documented JSON vector in Python and reproduces the Rust test's SHA256. This is a synthetic configuration oracle, not proof of a live distributed generation. R481 remains the last qualified full local CPU run and its former plan identity remains intact.
