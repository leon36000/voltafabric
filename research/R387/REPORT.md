# R387 — explicit unweighted FP32 native slot transport

The pinned Strata callback consumes unweighted float rows. R385's FP16 transport changes those rows: the nonzero synthetic test now explicitly exhibits at least one different FP32 bit pattern after FP16 round/decode. This commit adds a separately negotiated `cpu_strata_sc117_ggml_unweighted_f32_v1` session capability and `execute_native_fp32`, returning staged, finite unweighted FP32 rows with complete stamp, rank, attempt and slot identities. The Rust collector validates each slot and exposes unweighted rows only; no coefficient is applied and no FP32 preweighted reduction contract is selected. The ordinary FP16/f64 weighted collector path remains explicit and unchanged.

Two persistent local CPU child sessions with synthetic native weights return FP32 values bit-identical to direct native provider output, preserving external rows. The test demonstrates an FP16 rounding difference and verifies values greater than finite FP16 range remain valid through the FP32 slot path while the separate FP16 path still fails closed on overflow. A missing capability is refused before any request to either worker, without changing output. Existing local durable CPU reservation and whole-batch refusal apply. Actual gate coefficients and external completions remain the caller's responsibility.

This is a separate no-reduction FP32 boundary, not the Collector's preweighted FP32 contract; it does not prove Strata's actual callback is connected or its mixed GPU/peer synchronization is correct. R386 directly compared the provider with pinned generic Strata CPU and GGML, but AVX variants and real checkpoint outputs remain unqualified. No actual weights, GPU, inter-PC test, model-wide execution or generation is claimed. PC1 read-only check observed SC117 index SHA adba4968661f3d59f749a676a87948e29236c81997f649f5526daf71148edc24 and 147 GiB free at its mount; PC6 had ~220 MiB free swap, below the inter-PC admission threshold. Resource samples are not reservations.
