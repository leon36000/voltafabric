# R439 — append-only resident expert growth between CPU positions

Parent R438 `79e99f83f1f652e13c1d3b9ccdf98decd4a9e577`. A new, explicitly advertised CPU capability and request append a verified native GGML expert to an already sealed rank worker between synchronous executions. `RankWorker::add_owner` retains the existing physical positions, run/plan scope and attempt history, rejects duplicate expert or local IDs and differing rank/model/layer/epoch/index identities, and respects the existing per-rank count and byte limits. It does not evict weights. The original pre-seal load operation still rejects post-seal use.

`Segment::append_owner` updates its registry and resident order only after the worker confirms the matching binding. Any attempted append failure poisons the segment; a timeout or lost reply makes the session unusable, so uncertain loads must be reconciled and never blindly retried. The caller chooses the expert and placement and supplies the expected digest; this is not automatic route discovery, eviction, a production network transport, or an R53 hardware lease. As residents accumulate, explicit admission and memory budgeting remain essential.

One fresh PC1 CPU check ran QSA layer 3 followed by GDN layer 4 for two synthetic positions in one Segment. Each layer initially loaded only the first route's ten actual experts. After position 0, the diagnostic appended the ten additional actual experts needed by position 1 (four in layer 3 and six in layer 4) to the same four sessions, without replacing their original residents. Both output vectors compared equal as f32 values to a separate in-process preview sharing the provider and completion implementation; this is an integration check, not independent end-to-end parity. All four workers reported two executions and closed normally. `RESULT.json` SHA `e652bec5becf41da56e969e51cf9c60fe3f82494c58ef0d8333d9b683bcc17fe` contains the run, attempts, routes and hashes. `WEIGHTS.json` SHA `e69c6383cb973b19bbed241294749cf51a63714a89a9a893a4a50d9fb7a7efb0` records the 30 local expert hashes and byte equality to observed GGUF gate/up/down slices; these do not authenticate model provenance. Four corresponding local claims remain `RESERVED_UNKNOWN_NO_REPLAY`; do not replay them.

Three targeted append tests passed in debug and release: two real child-process executions around an append, duplicate rejection making the client terminal, and preservation of attempt/scope history and old physical positions. The existing seven native-provider tests passed in debug. The default-feature `a52_session` suite passed 28 tests after adding missing `required-features` declarations for eight recent native-only diagnostic binaries; previously the default build failed by compiling those feature-gated programs. Native-feature Clippy with warnings denied and formatting passed. No GPU or inter-PC worker ran.

The native computation reuses the pinned MIT GGML/llama.cpp and Strata boundary documented in `adapters/native_ggml/README.md`; quality is not inherited by assumption. Remaining work includes route-driven owner selection before dispatch, bounded residency/eviction or placement across the real fleet, a complete 48-layer model loader and generation loop, independent numerical parity, R428's expert-255 discrepancy, and hardware/network admission. The two inputs are synthetic and do not demonstrate token generation or measured performance.
