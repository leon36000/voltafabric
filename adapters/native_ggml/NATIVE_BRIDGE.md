# Local native-expert coordinator

Build with `native-ggml-cpu` and the pinned GGML CPU library described in this directory. `vf-strata-native-bridge` accepts one JSON value per line on stdin and writes one JSON reply per line on stdout. The first line is the `Init` structure in `src/strata_native_bridge.rs`: a validated routing template, complete model expert IDs, SC117 v3 index text, absolute pack path, absolute existing local ledger directory, local rank-session executables, per-expert bindings with trusted index and blob SHA-256, and timeout in milliseconds. The pack must be a regular file with the exact SC117 v3 size; the bridge reads and hashes only the selected bounded expert spans, checks the descriptor metadata remained stable, then loads and seals each resident once.

After `{"state":"ready",...}`, submit `{"op":"batch","batch":N,"tokens":T,"top_k":K,"inputs":[...],"ids":[...],"kinds":[...]}`. Inputs are token-major FP32; IDs and final ownership kinds are token/slot-major. `-1` selects a VoltaFabric CPU row; `0`, `1`, `2` designate external rows. The complete `{"state":"completed",...}` frame returns only CPU slot positions and their unweighted FP32 rows. The caller must validate the entire frame and synchronize external owners before writing any shared destination, and must apply gate coefficients once downstream. Ownership decisions and model/binding digests must come from a trusted source; the bridge cannot authenticate the donor's plan.

`{"op":"shutdown"}` closes and reaps the workers. On refusal, lost contact, malformed or incomplete frames, treat the batch as failed/UNKNOWN and do not publish a partial result or replay it. Every submitted CPU batch consumes a durable local claim before dispatch; retain and reuse the same ledger directory. This local ledger is not R53, a hardware lease, a distributed lock, or a result archive. This executable is not attached to Strata's actual callback and is not qualified for GPU, SSH/inter-PC workers, production networking, real model execution or complete generation. Only one absolute local executable per endpoint is accepted.

For a local C++ consumer, after `ready` send `{"op":"enter_binary"}` and wait for `{"state":"binary_ready"}`. The session is then binary-only. Each request is `VFB1`, little-endian u32 operation, u64 batch, u32 tokens and u32 top-k, followed for operation 1 by token-major FP32 bits, expert IDs and final kinds as little-endian 32-bit words. Tokens are 1–8, top-k 1–64, and slots at most 128. A reply is `VFR1`, little-endian u32 status, u64 batch, u32 row count and u32 columns, followed by each CPU position (u32) and 2560 FP32 words. Status 0 is complete, 1 is failure; operation 2 with other fields zero shuts down and returns status 2. The client must check the batch, all identities and exact CPU slot coverage before publishing any row.

`adapters/strata_native_bridge/pipe_client.hpp` provides a staging client for connected POSIX AF_UNIX stream sockets only; it takes already initialized read/write descriptors and makes them nonblocking. It does not spawn the coordinator, perform the JSON handshake, authenticate the initialization, own descriptors or connect to the actual Strata callback. Its deadline and a failed/partial frame make the client terminal, and the caller must treat the attempt as UNKNOWN. It deliberately never polls an rsocket handle. The caller is responsible for pinning the run/model/plan/layer/epoch in the preceding Init, and for draining any concurrent GPU/peer work and refusing downstream outputs on failure.

The optional `pool_cpu_only` adapter in `adapters/strata_native_bridge/pool_hook.hpp` matches the candidate boolean callback signature. A `PoolContext` binds one preinitialized binary client, one layer and the next unique batch number. It stages the complete callback output and latches failure, without fallback or retry. It supports only all-CPU expert slots; caller-owned GPU/peer/helper work is not accepted by the candidate donor patch.

`strata-fb58-cpu-hook.patch` is an **unqualified opt-in candidate**, never applied automatically. It adds the hook fields at `ExpertDispatch`, admits only SC117 CPU-only expert calls at the donor's actual multi-pool site, changes the four CUDA verifier pool calls to observe a boolean error, and requests the existing GPU wait-release path on failure. It also stops treating a CUDA stream-query error as a successful drain. `make_reference_patch.py` requires the exact clean donor revision; `check_reference_patch.py` checks application to a private overlay and syntax only. The patched donor has not been linked, executed or qualified with a model or GPU, and the candidate does not configure hook contexts or manage their lifecycle. Do not enable it in a live service until the full ownership, signal, drain and model tests pass under the hardware gates.

For the isolated donor-branch test, pass a fifth output path to `check_reference_patch.py`. The script compiles a test executable containing the exact patched prefix of `expert_pool_dispatch_multi`; its ordinary donor fallback and CUDA verifier are deliberately excluded. Set `VF_STRATA_CPP_DONOR_BRANCH` to that executable when running the synthetic `strata_native_provider` integration test. This proves the extracted CPU-only branch reaches the native bridge, not that the full donor executable or any GPU failure path is qualified.

For a stronger isolated dispatch test, pass `2 full` after the output executable path to `check_reference_patch.py`, then set `VF_STRATA_CPP_DONOR_FULL` to that executable for the synthetic integration test. This compiles and links the complete patched `expert_source.cpp`, not only the extracted branch. All unavailable CUDA, peer and original CPU fallback entry points are test-only aborting stubs, and the executable has no CUDA runtime dependency. It tests only the opt-in CPU path and guard refusals; it does not run the actual verifier or qualify the donor engine.

The C++ client uses VFB2/VFR2, which adds a little-endian u32 layer after each 24-byte header. The coordinator rejects a mismatched requested layer before reserving or executing a batch; the client verifies the layer in every response. VFB1 remains available for older explicitly managed consumers and does not carry this check. The layer check does not authenticate the run, model, plan or epoch: the caller must still bind the socket to the trusted Init. The C++ client and `PoolContext` must name the same layer.

`PoolFleet` maps up to 48 layer numbers to separately initialized `PoolContext`s and supplies `pool_cpu_by_layer` with the same callback signature as `pool_cpu_only`. Mapping is immutable after construction; calls are serialized, and a missing or misbound layer or a child failure latches the whole fleet. Contexts, sockets, initialization, model/plan consistency, owner identity, unique batch assignment and orderly closure remain the caller's responsibility. This does not create, schedule, or qualify a full-model engine; it is a local CPU-only building block.
