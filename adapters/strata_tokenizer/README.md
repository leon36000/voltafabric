# SC117 tokenizer adapter

`adapter.py` loads the four caller-pinned SC117 tokenizer pack files, checks bounded regular-file reads and hashes, validates the observed Qwen35 vocabulary and merges, and delegates byte-level BPE to Strata's tokenizer. `GreedyDecoder` preserves UTF-8 across token boundaries, stops explicitly at EOS and refuses unexpected control tokens. `decode_greedy_receipt` validates the structure of an authenticated-by-caller R459/R462-style receipt with at most three positions, then returns complete decoded text or an error without a partial result. It does not implement a chat template, sampling policy or model generation.

`vendor/strata_tokenizer.py` and `vendor/gguf_reader.py` are unmodified from Strata commit `fb58e0dbc8399662c0e47c76578c6e878b14f6cf` (MIT; copyright and license in `vendor/LICENSE`). SHA256 values are respectively `9b0327e25aa62754406a924db6cc137e6edb1d93c7af76a4f3d14a8920ea72c8` and `5ecf739bb3c2f07bc7f889f7f3a455e3dfdb40068409e10781a1a9b2be289b5e`. The existing Python `regex` package is required; it is not vendored. R460 records the version used and what was checked. Donor behavior is a starting point, not a quality guarantee.

`observed-sc117.json` records hashes observed locally; they identify files but do not authenticate the publisher. Callers must establish provenance and provide trusted digests. The associated tokenizer files are not included in the repository. `research/R460/qualify_tokenizer.py` compares the pack to a local GGUF header without reading model tensors; evidence does not qualify every encode/decode case or the full model.

`python -m adapters.strata_tokenizer.prompt_runner` reads the prompt from standard input and runs the pinned `vf-sc117-prompt-greedy` executable once using explicit absolute model, worker and ledger paths. This experimental path accepts one or two ordinary prompt tokens and emits at most two greedy tokens. It performs no chat templating. Caller-supplied executable and tokenizer hashes verify local bytes, not publisher provenance; resource admission, exclusive workers and a fresh durable ledger are the caller's responsibility. It does not retry failed or uncertain work. After a failure reconcile the ledger and never replay UNKNOWN claims. The CLI prints one complete JSON receipt only after tokenization, engine completion, worker shutdown and decoding succeed.
