# SC117 tokenizer adapter

`adapter.py` loads the four caller-pinned SC117 tokenizer pack files, checks bounded regular-file reads and hashes, validates the observed Qwen35 vocabulary and merges, and delegates byte-level BPE to Strata's tokenizer. `GreedyDecoder` preserves UTF-8 across token boundaries, stops explicitly at EOS and refuses unexpected control tokens. `decode_greedy_receipt` validates the structure of a caller-authenticated greedy receipt within the current 128-position bound, then returns complete decoded text or an error without a partial result. It does not implement a chat template, sampling policy or model generation.

`vendor/strata_tokenizer.py` and `vendor/gguf_reader.py` are unmodified from Strata commit `fb58e0dbc8399662c0e47c76578c6e878b14f6cf` (MIT; copyright and license in `vendor/LICENSE`). SHA256 values are respectively `9b0327e25aa62754406a924db6cc137e6edb1d93c7af76a4f3d14a8920ea72c8` and `5ecf739bb3c2f07bc7f889f7f3a455e3dfdb40068409e10781a1a9b2be289b5e`. The existing Python `regex` package is required; it is not vendored. R460 records the version used and what was checked. Donor behavior is a starting point, not a quality guarantee.

`observed-sc117.json` records hashes observed locally; they identify files but do not authenticate the publisher. Callers must establish provenance and provide trusted digests. The associated tokenizer files are not included in the repository. `research/R460/qualify_tokenizer.py` compares the pack to a local GGUF header without reading model tensors; evidence does not qualify every encode/decode case or the full model.

`python -m adapters.strata_tokenizer.prompt_runner` reads a bounded text prompt or JSON chat history from standard input and starts the explicitly selected SC117 coordinator once. The experimental contract permits up to 128 prompt tokens and 128 predictions with `prompt length + requested predictions - 1 <= 128`. Only the observed local SC117 CPU path has been demonstrated; full-model parity, GPU and inter-PC execution are not qualified by this adapter.

On Linux the CLI checks the caller-supplied executable SHA256, copies the bounded ELF into a sealed in-memory descriptor, and runs that snapshot. This prevents a later path replacement or in-place modification of the source file from changing the launched bytes. It requires Linux memfd, sealing and executable `/proc/self/fd` support and can use up to the 128 MiB executable cap in additional memory. Scripts are refused. Direct library callers of `run_prompt` must still authenticate their own execution path unless they pass a verified sealed descriptor. Caller-supplied hashes identify local bytes, not publisher provenance. Resource admission, exclusive workers and a fresh durable ledger remain the caller's responsibility. The runner does not retry failed or uncertain work; reconcile the ledger and never replay UNKNOWN claims. The CLI prints one complete JSON receipt only after tokenization, engine completion, worker shutdown and decoding succeed.
