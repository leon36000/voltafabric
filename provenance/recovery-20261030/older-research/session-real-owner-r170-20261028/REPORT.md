# R170 — vraie Session Rust et vrais owners persistants, fournisseur CPU de test

La commande Rust `session-run-compressed` a lancé deux endpoints Python de recherche. Chacun reçoit le véritable artefact QPN2 du coordinateur, vérifie son SHA et son identité, le stocke dans un fichier neuf isolé, puis charge le vrai `PersistentQPN2Owner` avec un fournisseur CPU de test empruntant le décodage et les produits R156/R158. Une requête FP16 est transmise à chaque owner ; ses sorties réelles sont cadrées avec `OwnerOutput.as_raw_output_bytes` et les helpers R162, puis lues par la Session et son Collector Rust. Le owner garde les poids résidents pendant l'EXEC et se ferme sur SHUTDOWN. Les deux rangs effectuent chacun deux projections CPU synchronisées.

Cas nominal : `python3 -B test.py`, exit 0 ; run final `r170-3c16d299a578453291fa9e32dafa200e`. Une tranche, deux owners, deux EXEC, deux BYE, les 2048 résultats correspondent exactement à l'oracle externe `0,75 ×` la ligne de référence R158. L'oracle dense intégré est vérifié à tolérance expérimentale 0,01 ; écart max ~9,64e-6. Cette tolérance n'est pas un seuil de qualité modèle. Le test rouge initial a échoué parce que le worker n'existait pas ; un test nominal précédent a aussi réussi avant l'ajout du chemin de faute.

Cas négatif distinct `r170-277426ae5777490f81c47525f57c9c90` : une exception synthétique dans le fournisseur CPU après admission et STARTED ferme le worker. La Session renvoie `SESSION_CLOSED`, marque le rang 2 `unknown`, n'enregistre aucun résultat du batch et refuse la sortie partielle ; ce run est consommé et ne doit jamais être rejoué. `python3 -B negative.py` vérifie le reçu et sort 0, commande Session exit 2. Les tests produisent une nouvelle identité UUID à chaque exécution, et les reçus et entrées historiques restent dans ce dossier.

Portée : un batch nominal avec deux copies synthétiques d'un seul expert échantillonné, local en processus, fournisseur numérique CPU de test. Le worker est privé, borné à ce cas, et annonce des capacités HELLO nécessaires au coordinateur qu'il ne généralise pas. Pas d'intégration moteur 1Cat, modèle entier, réseau de production, CUDA, V100 ni comparaison de vitesse. L'échec ne teste pas un redémarrage ou la conservation du poison à travers un service externe. Aucune source canonique modifiée et aucune publication Git.

Suite : généraliser uniquement après tests multi-batch/poids résidents, états et erreurs pré-admission, sorties incomplètes, et revue indépendante des identités et de la machine de protocole ; améliorer le traitement de l'échec après admission sans replay UNKNOWN. Garder le fournisseur CPU de test distinct de tout fournisseur GPU.
